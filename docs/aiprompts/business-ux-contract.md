# 业务型 UI 契约

本文件用于约束布谷AI内容工厂的桌面端 UI / UX 设计、原型生成和页面改造。目标是让 Codex 和大模型后续默认设计“真实业务工作台”，而不是功能介绍页。

## 使用时机

涉及以下任务时先读本文件：

- 生成或重做桌面端原型。
- 修改普通用户主工作台页面。
- 评审截图、交互流或 UI 文案。
- 把 PRD / 用户故事转成页面。
- 调整输入源、知识库、Prompt、SOP、审核、素材库、运行历史等业务页面。

## 核心判断

一个合格页面必须先回答业务问题，再回答视觉问题：

- 用户是谁。
- 用户此刻要完成什么业务任务。
- 用户正在处理哪个业务对象。
- 输入从哪里来，哪些资料缺失。
- 用户需要判断、选择或补充什么。
- 页面唯一主动作是什么。
- 系统如何反馈进度、缺口、风险和结果。
- 异常状态如何恢复。
- 完成后产物交付到哪里。

如果页面主要由导航、功能卡片、状态胶囊、入口按钮组成，但看不出一个业务对象正在被处理，判定为失败。

## UI 契约模板

生成原型、截图提示词或 UI 代码前，先写下面的契约：

```text
业务 UI 契约：
PRD 映射：
- 用户故事：[US-xx]
- 用户用例：[UC-xx]
- 端到端路径：[路径名称]
- 验收标准：[对应验收条件]

目标用户：[新媒体运营 / 电商运营 / 短视频运营 / 审核人员 / 内容工程师]
用户任务：[用户此刻要完成的真实业务任务]
业务对象：[正在处理的输入源 / 场景卡 / Prompt 草稿 / 素材 / 审核任务 / 运行记录]
输入物：[DOCX / Markdown / 参考图 / 产品资料 / SKU 表 / 用户评论 / 历史素材]
当前状态：[待解析 / 缺资料 / 可运行 / 生成中 / 待审核 / 已驳回 / 已交付 / 待配置]
主路径：[第 1 步 -> 第 2 步 -> 第 3 步 -> 交付]
用户决策点：[用户需要判断、选择、补充或确认的事项]
系统反馈：[来源追溯 / 缺口提醒 / 质检结果 / 审核状态 / 交付状态]
异常恢复：[资料缺失 / 生成服务待配置 / 合规风险 / 审核驳回 / 文件解析失败]
最终交付物：[Prompt 草稿 / 场景库 / 图片素材 / 视频 Prompt / 混剪素材包 / 发布文案]
完成定义：[用户完成后能直接进入哪个下游动作]
```

## 页面组织规则

- 左侧保留现有导航和当前任务上下文，不新增另一套 SaaS 式导航。
- 中间必须展示当前业务对象和主处理区，不做能力目录。
- 右侧展示来源追溯、模型参数、审核清单、资料缺口或恢复路径。
- 同一页面只保留一个当前主动作；辅助动作必须围绕当前对象。
- 空态不能只说“暂无数据”，必须告诉用户补什么资料或去哪个入口恢复。
- 状态不能只是标签，必须影响下一步动作和按钮可用性。
- 表格、卡片和流程导轨必须服务用户判断，不为凑信息密度而堆叠。

## 反功能平铺门禁

出现以下任一情况，先重写契约，不进入原型或代码实现：

- 页面标题和卡片都在介绍系统能力，但没有正在处理的对象。
- 多个主按钮权重相同，用户不知道下一步点什么。
- 只展示“已完成 / 待处理 / 可用”等状态，但没有状态背后的资料、风险或恢复路径。
- 把 Prompt 工作台、SOP、场景库、输入源等都做成并列入口，没有业务路径。
- 用户完成动作后不知道产物进入图片生成、视频 Prompt、审核、素材库还是导出包。
- 页面需要用户理解工程术语才能继续操作。

禁用表达：

- `功能概览`
- `能力中心`
- `功能清单`
- `入口合集`
- `模块入口`
- `功能罗列`
- `Provider`
- `blocked`
- `manifest`
- `PromptRef`

普通用户可见替代表达：

- `Provider` -> `生成服务`
- `blocked` -> `待配置` / `暂不可用`
- `manifest` -> `混剪清单`
- `PromptRef` -> `提示词来源`
- `artifact` -> `素材` / `产物`
- `run` -> `运行记录`

## 可直接复用的提示词

```text
你不是在设计功能介绍页，而是在设计布谷AI内容工厂桌面端业务工作台。

先输出业务 UI 契约，不允许直接生成界面：
1. PRD 映射
2. 目标用户
3. 用户任务
4. 业务对象
5. 输入物
6. 当前状态
7. 主路径
8. 用户决策点
9. 系统反馈
10. 异常恢复
11. 最终交付物
12. 完成定义

然后再生成 UI。

UI 规则：
- 禁止功能罗列、能力概览和入口合集。
- 必须展示一个正在被处理的真实业务对象。
- 必须有输入、处理、审核或交付闭环。
- 必须有资料缺失、待配置、待审核或驳回恢复路径。
- 每页只有一个当前主动作。
- 每个区域必须回答：用户现在看什么、判断什么、点什么、得到什么。
- 保留布谷AI桌面端三栏工作台：左侧导航，中间任务区，右侧来源 / 参数 / 审核栏。
```

## 验收清单

- 页面能追溯到 `US-xx`、`UC-xx` 和端到端路径。
- 页面展示了当前业务对象，而不是功能入口矩阵。
- 主动作唯一且清晰。
- 资料缺口和异常恢复可见。
- 完成后交付物和下游去向可见。
- 普通用户不需要理解工程术语。
- 不把 Canvas 作为普通用户主路径。
- 不把第三方视频生成写成软件内外部任务闭环。
