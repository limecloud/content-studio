# 布谷AI内容工厂 v2 路线图

更新时间：2026-05-22
状态：Local Verified / 等待真实验收
参考来源：v1 路线图、用户补充的伙伴猫内容系统诉求、楚川老师课程截图、图片 / 视频 SOP 案例、canvas 工作流讨论、视频成本与第三方混剪边界讨论、楚川补充的品牌场景提示词链路和 IP 知识库体系截图

## 一句话目标

把布谷AI内容工厂 v2 做成 **客户端里的知识体系 + 场景库 + Prompt 生产 + 素材生成** 的 AI 内容素材工厂：品牌 / 产品知识库先沉淀场景库，再生成图片 / 视频提示词；IP 知识库作为个人 IP 全面运营底座，继续延伸出口播、文案、私域、产品化等场景知识库。

```text
布谷AI内容工厂 v2 = 品牌 / 产品知识库 -> 场景库 -> 提示词组 -> 图片 / 视频素材
                 + IP 知识库 -> IP 运营场景库 -> 文案 / 脚本 / 私域 / 产品化资产
```

## 产品定位

- **面向用户**：品牌运营、新媒体运营、短视频团队、电商内容团队、个人 IP 内容团队。
- **核心对象**：品牌 / 产品知识库、IP 知识库、场景库、场景卡、提示词组、参考图、参考视频、产品资料、Agent 会话、用户意图、Prompt 草稿、提示词包、SOP、Skill、图片素材、视频片段任务、绿幕文案图、混剪素材包、生成日志。
- **首要场景**：围绕一个品牌 / 人设 / 产品，把已整理知识转成多个平台可用的内容素材，而不是直接做完整剪辑软件或全自动发布系统。
- **产品形态**：本地客户端 / 桌面工作台，不是 SaaS 后台。数据优先落在本地工作区 `.content-studio/`，模型和外部平台通过用户配置的生成服务调用。
- **工程边界**：v2 不做复杂后端、多租户协作、SaaS 计费后台、完整视频剪辑时间线和自研混剪；这些不进入当前客户端主线。

## v2 核心主链

```text
品牌 / 产品素材生产：
品牌 / 产品知识库
-> 场景库
-> 提示词组
-> 图片 / 图生视频 Prompt
-> 外部生成工具或内部生成 API
-> 审核 / 素材库 / 混剪包
```

```text
个人 IP 内容运营：
个人 IP 原始素材
-> IP 知识库
-> IP 运营场景库
-> 文案 / 脚本 / 私域 / 产品化提示词
-> 场景延伸知识库
-> 内容资产和运营资产
```

## v2 与 v1 的关系

v1 已经建立：

- 已成型知识库。
- 提示词包。
- 场景卡。
- 文章生成。
- 图片生成。
- 视频脚本 / 视频队列雏形。
- 素材库和生成历史。

v2 不推翻现有客户端，也不把现有图片 / 视频 / 文案 / 知识库模块替换成一套新的 SaaS 信息架构。v2 是在当前可用模块上升级：图片生成继续作为主入口之一；视频模块继续保留爆款拆解、脚本、视频 Prompt 和可选队列；知识库模块拆出品牌 / 产品知识库和 IP 知识库；素材库从生成历史升级为可复用资产库。

v2 要修正主链路：知识库不是一个泛化附件，而是分为品牌 / 产品知识库和 IP 知识库。品牌 / 产品知识库需要先抽成场景库，再生成提示词；IP 知识库是个人 IP 全面运营底座，后续会延伸出口播、文案、私域、产品化等场景知识库。对标图、参考视频、产品资料、SKU 表和竞品内容仍然可以直接成为 SOP 的事实源。

```text
KnowledgeBase / InputSource
  -> BrandKnowledgeBase / IpKnowledgeBase / Reference Image / Reference Video / Product Brief
  -> SceneLibrary / Agent Session / Vision Analysis / Prompt Reverse Engineering
  -> Prompt Group / Prompt Draft
  -> SOP Run / 生成任务
  -> Artifact / 素材库
```

## 关键产品判断

1. **输入源不只知识库**：知识库文档、参考图、参考视频、产品资料和竞品内容都可以驱动 SOP。
2. **品牌链路必须有场景库**：品牌 / 产品知识库不能直接跳 Prompt；先抽场景，再生成可复制提示词。
3. **IP 知识库是独立体系**：IP 知识库覆盖身份、价值观、语言、方法论、素材和创作引擎，不只是人设简介。
4. **大模型玩法先行**：读文档、看图反推、视频拆解、平台改写、批量变体、质检评分都是核心玩法。
5. **先多轮跑通再产品化**：手工 / Agent 多轮调整 -> Prompt 固化 -> SOP 文档化 -> Skill 封装 -> 平台化。
6. **SOP 是生产方法**：小红书、公众号、抖音、B 站、详情页不是不同系统，而是不同工作流定义。
7. **canvas 是编辑视图，不是事实源**：工作流事实源必须是可版本化、可 diff、可执行的定义；canvas 只负责可视化。
8. **视频是素材片段生产，不是成片剪辑**：软件生成或组织 15 秒视频 Prompt、可选视频素材、绿幕文案图和混剪清单；第三方视频生成由用户手动复制 Prompt 完成，成片混剪交给第三方工具。
9. **人工审核必须保留**：AI 给候选结果，人确认后进入可交付状态。
10. **现有图片 / 视频能力必须保留**：图片生成对当前用户直接有价值，是素材生产的核心入口；视频内部 API 生成不是当前主卖点，但视频拆解、视频脚本、视频 Prompt、成品导入和混剪素材包对当前短视频用户有价值。
11. **客户端优先**：所有设计先按单机工作区、本地文件、用户自配生成服务、可导出素材包来设计；云协作、团队权限和计费后台不作为 v2 目标。

## v2 非目标

- 不做完整视频剪辑软件。
- 不做多轨时间线、转场、音频轨精修和成片渲染。
- 不默认全自动发布，发布草稿和人工确认优先。
- 不把 canvas 拖拽作为唯一交互。
- 不做复杂后台和多人权限系统。
- 不做 SaaS 产品形态、租户体系、服务端计费后台和云端素材协作。
- 不做不可追溯的 AI 自动编造卖点。
- 不强制把知识库先拆成复杂数据库结构。
- 不把 Agent 多轮理解简化成一次性 RAG 摘要。
- 不把所有 SOP 都强行绑定知识库。
- 不把品牌 / 产品知识库直接当 Prompt 列表；中间必须有场景库或内容任务结构。
- 不把 IP 知识库简化成人设简介或品牌知识库子类型。
- 不在流程没跑稳前强行封装复杂自动化。
- 不伪造视频或图片生成成功；未配置生成服务时输出可追溯的待配置 / 待外部处理状态。

## 完成定义

v2 可宣称完成需要同时满足：

- 能导入至少 2 类知识库文档：个人 IP 知识库和品牌 / 产品知识库，并转换为可读 Markdown / 文本索引。
- 品牌 / 产品知识库能抽取场景库，并从场景库生成 10 组可复制的 UGC 实拍图片 / 图生视频提示词。
- IP 知识库能按六层结构展示完整度，并能继续生成口播、文案、私域、产品化等场景延伸知识库。
- 能在无知识库情况下，基于参考图和产品资料反推出 Prompt 并生成同风格图片。
- Lime App Server Agent 能基于知识库文档和用户意图多轮生成、修改并确认 Prompt。
- 能创建、查看、运行至少 3 个 SOP 工作流：小红书种草、公众号长图文、图片 / 详情页素材。
- 工作流定义能版本化保存，运行记录能追溯输入源、步骤、模型、来源引用和产物。
- 图片素材、文案草稿、绿幕文案图、视频 Prompt 和可选导入视频能统一入库。
- 视频支持内部 API 生成与人工复制 Prompt 到第三方平台两条路径，并能清楚展示成本 / 边界差异。
- 素材库支持标签、平台、状态、来源和复用。
- 混剪素材包能导出素材文件夹和混剪清单文件，供第三方混剪软件使用。
- 人工审核步骤能标记通过、驳回、重生成或进入素材库。
- 关键路径有本地验证，失败状态不靠跳过或伪造绕过。
- 发布级完成必须通过 `npm run verify:v2:release -- --workspace <工作区路径> --output-dir docs/dev/v2-acceptance/<日期>`；该入口固定要求真实生成服务严格联调、真实工作区闭环、真实混剪导入证据、网络联调和媒体联调，不能用本地样例或配置诊断代替。

当前只剩三类发布级证据待补：

1. 真实生成服务严格联调：文字、视觉理解、图片和视频生成服务全部通过。
2. 真实业务工作区闭环：真实品牌 / IP / 产品 / SKU / 评论 / 参考图 / 参考视频跑完整主链。
3. 真实第三方混剪导入：混剪包在真实工具导入成功，并留存 `import-evidence.json`、截图 / 录屏 / 验收记录。
