# 布谷AI内容工厂 v2 知识体系修订

更新时间：2026-05-21
状态：Draft
参考来源：楚川补充截图、品牌场景提示词示例、嘉文老师 IP 知识库样例、用户补充说明

## 1. 核心修正

v2 不能再把“知识库”当成一个泛化附件。至少要拆成两套不同体系：

```text
品牌 / 产品知识库
-> 场景库
-> 提示词组
-> 图片 / 图生视频 Prompt
-> 外部生成工具或内部生成 API
-> 审核 / 素材库 / 混剪包
```

```text
个人 IP 原始素材
-> IP 知识库
-> IP 运营场景库
-> 文案 / 脚本 / 直播 / 私域 / 产品化提示词
-> 场景延伸知识库
-> 内容资产和运营资产
```

第一条链路面向品牌、产品和商业素材生产。第二条链路面向个人 IP 的长期运营，不只是生成几段内容，而是构建一套可复用的人设、观点、语言、方法论和内容引擎。

## 2. 品牌 / 产品知识库链路

品牌 / 产品知识库的目标不是直接吐 Prompt，而是先抽出可生产的“场景库”。场景库是 Prompt 前面的中间层。

### 2.1 输入

- 产品知识库 DOCX / Markdown / PDF 转文本。
- 品牌调性、产品卖点、适用人群、合规边界。
- 季节、节日、平台和投放目标。
- 用户问题、评论、差评、客服问答。
- 参考图和参考视频。

### 2.2 场景库

场景不是一句 Prompt。一个场景至少应包含：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 人群 | 谁出现在画面里 | 3-6 岁儿童、妈妈、家庭成员 |
| 触发问题 | 场景里的真实困扰 | 夏季吹空调后咳嗽、泳池后揉眼、蚊虫叮咬红肿 |
| 时间 / 季节 | 场景发生时间 | 夏季、傍晚、午后 |
| 空间 | 场景位置 | 客厅、儿童房、泳池边、户外公园、厨房 |
| 动作 | 人物正在做什么 | 妈妈递水、孩子揉眼、孩子挠手臂 |
| 情绪 | 画面情绪 | 温馨、担心、真实、生活化 |
| 镜头 | 画面视角 | UGC 手机实拍、自然光、轻微抓拍感 |
| 合规边界 | 不能表达什么 | 不出现医疗承诺，不暗示治疗 |
| 输出用途 | 用于什么 | 图片生成、图生视频、封面图、脚本分镜 |

### 2.3 提示词组

提示词组从场景库生成，要求可直接复制到外部图片 / 视频生成工具。每条提示词应尽量具体：

- 人物：年龄、身份、状态。
- 场景：空间、时间、光线、环境物件。
- 动作：具体动作和交互。
- 镜头：手机实拍、竖屏、近景 / 中景、自然抓拍。
- 质感：无 AI 感、无滤镜感、生活化、皮肤和细节真实。
- 约束：不夸张、不医疗化、不摆拍、不广告棚拍。

示例链路：

```text
唯他瑞葡聚糖知识库
-> 夏季儿童免疫相关场景库
-> 10 组 UGC 实拍提示词
-> 外部图片生成工具
-> 图生视频 Prompt
```

## 3. IP 知识库体系

IP 知识库不是品牌知识库的子类型，也不是简单“人设资料”。它是个人 IP 全面运营的底座。

以 `嘉文老师_IP知识库_v1.0.docx` 为例，IP 知识库应至少包含六层：

1. **身份锚定层**：基础档案、一句话定位、核心标签、职业履历时间线。
2. **价值观与立场层**：核心价值观、明确观点、边界清单、不会说的话。
3. **声音与语言质感层**：语言风格、口头禅、标志性句式、金句库、类比偏好。
4. **判断力与决策逻辑层**：核心方法论、评估模型、处理问题的推理方式。
5. **内容素材库层**：完整故事、案例、时间线、情节、转折和可用场景。
6. **内容创作引擎层**：平台 SOP、爆款结构、禁区清单、可直接调用的系统提示词段落。

IP 知识库的目标是支撑长期运营：

- 朋友圈文案。
- 视频号 / 抖音口播脚本。
- 小红书笔记。
- 公众号长文。
- 直播话术。
- 家长咨询回复模板。
- 付费产品介绍和转化内容。
- 私域社群内容。
- 个人 IP 产品化材料。

## 4. 场景延伸知识库

IP 知识库建成后，还会衍生多个场景知识库。这些不是重新做人设，而是在同一 IP 底座上扩展运营场景。

示例：

| 延伸知识库 | 作用 |
| --- | --- |
| 口播逐字稿库 | 生成 30 秒 / 2-3 分钟 / 深度口播稿。 |
| 文案改写库 | 保留 IP 语气，把普通文案改成有爆款特质的版本。 |
| 付费产品转化库 | 把文章或方案改成 Word 付费产品、销售页或私域转化材料。 |
| 家长咨询问答库 | 按 IP 立场生成咨询回复和异议处理。 |
| 热点改写库 | 把热点事件改写为符合 IP 调性的内容。 |

这些延伸库必须引用同一个 IP 知识库版本，避免每个场景各自发明一个人设。

## 5. 产品结构影响

因此 v2 的信息架构需要新增或强化：

- **品牌知识库**：品牌 / 产品资料、合规边界、产品事实。
- **IP 知识库**：个人 IP 六层体系、版本、素材完整度。
- **场景库**：从品牌 / 产品 / IP 知识库抽出的可生产场景。
- **提示词库**：从场景库生成的图片、视频、文案、脚本提示词。
- **场景延伸库**：围绕 IP 的口播、私域、产品化、咨询、热点等场景资产。

## 6. 设计边界

- 不把 IP 知识库和品牌 / 产品知识库混成一个表。
- 不从知识库直接跳到图片生成，中间必须有场景库或内容任务结构。
- 不把场景库写成 Prompt 文本列表；场景要结构化，Prompt 是下游产物。
- 不把 IP 知识库简化成人设简介；必须支持价值观、语言、方法论、素材和创作引擎。
- 不把外部图片 / 视频生成平台当成软件内任务；软件只负责提示词、素材导入和追溯。

## 7. 当前落地映射

当前客户端先保留两层事实源：

| 层级 | 现有实现 | 说明 |
| --- | --- | --- |
| 成型知识库 | `KnowledgeBaseStore` | 导入 DOCX / Markdown / JSON 后拆成章节，可检索并形成 `KnowledgeCitation`。 |
| 工作流输入源 | `InputSourceStore` | 登记 DOCX、Markdown、文本、图片、视频和成功素材；可读文本写入 `extractedText` 与 `markdownPath`。 |
| 提示词包 | `PromptPackService` | 接收手动引用、检索引用、当前知识库重点章节或已解析输入源引用，调用文字模型生成品牌 / IP 提示词包。 |
| 场景库 | `SceneLibraryStore` | 基于提示词包生成结构化 `SceneCard`，再进入图片 / 视频 PromptDraft。 |
| Prompt 草稿 | `PromptDraftStore` | 选择输入源、场景卡和用户意图，优先由文字模型生成；未配置时 blocked / 本地降级并保留来源。 |

这意味着现阶段已打通的最小链路是：

```text
DOCX / Markdown
-> extractedText / markdownPath
-> KnowledgeCitation
-> PromptPack
-> SceneCard
-> PromptDraft
-> 图片 / 视频 Prompt / 绿幕图 / SOP 草案
```

后续需要把 `InputSourceStore` 中的品牌 / 产品与 IP 输入源继续沉淀为专用 `BrandKnowledgeBase` 和 `IpKnowledgeBase`，避免长期只靠泛化输入源承载六层 IP 体系。
