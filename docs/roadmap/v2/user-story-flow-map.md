# 布谷AI内容工厂 v2 用户故事流程重审

更新时间：2026-05-22
状态：Draft / 按普通用户主路径继续校准

## 1. 重审结论

v2 不能再按“对象已经存在”判断完成。普通用户不会先理解 `WorkflowDefinition`、`PromptDraft`、`artifactRefs` 或 canvas 节点；他们只关心：我从哪里开始、现在缺什么、点哪个主按钮、完成后去哪里审核 / 入库 / 导出。

本轮把所有用户故事按同一条可执行契约收敛：

```text
入口可发现
-> 资料可登记或临时粘贴
-> 表单能运行
-> 待配置 / 待补齐有恢复路径
-> 下一步进入业务工作台
-> 产物可审核 / 入库 / 导出
-> 运行记录可追溯
```

普通用户主路径允许两种资料方式：

- 已登记资料：从“输入源 / 文档转换”登记知识库、产品资料、评论原声、参考图、参考视频或历史素材。
- 临时资料：在 SOP 表单的“补充资料说明”里粘贴本次 brief、评论、脚本或本地文件路径；运行时自动登记为本次可追溯输入源。

临时资料不是绕过追溯。后端会把它写成 `workflow-run` 输入源，并进入同一条运行记录；真实发布验收仍要求用真实工作区、真实 provider 和真实业务素材补齐证据。

## 2. 全局流程规则

| 规则 | 产品含义 | 实现 / 验收约束 |
| --- | --- | --- |
| 普通用户不用 canvas | 日常生产从图片、视频、文案、知识库、资产里的表单进入。 | Canvas 只在“高级维护”中可见，不作为运行事实源。 |
| 品牌资料不能直接跳 Prompt | 品牌 / 产品知识库先生成场景库，再生成提示词组。 | `brand-scene-prompts` 必须保留品牌知识库、场景卡和 Prompt 草稿引用。 |
| IP 知识库不是品牌字段 | IP 必须按六层体系构建，并延伸到口播、私域、产品化等场景。 | `ip-longform` 和 IP 场景延伸必须关联同一 IP 知识库版本。 |
| 无知识库路径必须存在 | 对标图、产品 brief、评论原声、参考视频可以直接驱动 SOP。 | 不强制先建知识库；但图片 / 视觉 / 文本 provider 未配置时底层保持 `blocked`，普通用户界面显示“待配置”并给恢复路径。 |
| 视频第三方生成脱离软件 | 软件只生成 Prompt、记录复制动作、允许手动导入成品。 | 不创建 RunningHub 任务，不轮询第三方状态，不伪造视频完成。 |
| 审核是交付门槛 | AI 只给候选，人工决定通过、驳回、回炉或入库。 | 素材库、混剪包和平台草稿包必须能回到 runId、输入源和 Prompt 版本。 |

## 4. 当前修正点

### 4.1 SOP 表单不能强制先登记资料

旧问题：SOP 表单要求必须勾选已有输入源。普通用户已经粘贴了产品 brief、评论原声或脚本时仍不能运行，导致“表单化执行”变成不可用。

新规则：

- 有已登记资料时，默认推荐并可取消选择。
- 没有已登记资料时，允许用户在“补充资料说明”粘贴本次资料后运行。
- 运行后这段临时资料自动变成 `workflow-run` 输入源，进入同一份 runId 追溯。
- 如果既没有勾选资料，也没有粘贴资料，运行按钮继续禁用，并给出“去登记资料”恢复路径。

### 4.2 待配置必须变成恢复路径

`blocked` 是底层状态码，不是普通用户文案。普通用户只需要看到“待配置 / 待补齐 / 待解析”和下一步：

- 缺产品资料：去“输入源 / 文档转换”补产品 brief、SKU 或详情页。
- 缺评论原声：去登记评论、差评、客服问题或私信。
- 缺视觉 provider：去配置真实视觉理解服务，不能用文字模板伪造看图。
- 缺图片 provider：底层保留 `blocked`，界面显示待配置，不显示占位图。
- 视频 Prompt 已复制：去“成品视频导入”，不要在软件里找第三方任务状态。

### 4.3 完成度必须回到真实业务证据

local-sample 只能证明结构没有坏，不能证明 v2 完成。真实完成必须从工作区读取证据：

```bash
CONTENT_STUDIO_PROVIDER_CHECK_ALLOW_NETWORK=1 CONTENT_STUDIO_PROVIDER_CHECK_ALLOW_MEDIA=1 \
npm run verify:v2:evidence -- --provider-strict --require-real-workspace-evidence --require-external-mix-evidence --workspace <真实工作区路径> --output-dir docs/dev/v2-acceptance/<日期>
```

### 4.4 混剪导出后必须有普通用户可登记的外部导入证据

旧问题：`US-08 / UC-12` 只导出了 manifest 和导入说明，剪辑人员是否真的把素材导入剪映 / CapCut / Premiere 只能靠手工把 `import-evidence.json` 放进目录，App 内没有连贯入口。

新规则：

- 混剪包历史卡必须显示“待登记导入证据 / 导入证据已登记”，普通用户不需要打开目录手写 JSON。
- 登记表单只收业务信息：第三方工具、导入时间、验收人、已导入素材、文件数、manifest 核对、时间线 / 工程创建、验收结果、证据文件和备注。
- 保存后写入混剪包目录的 `import-evidence.json` 和 `import-check.md`，并把证据路径回写到视频素材包 SOP 运行记录。
- App 内登记只是让真实证据可追溯，不伪造第三方混剪成功；发布验收仍要求截图、录屏或剪辑验收记录来自真实外部工具。

### 4.5 视频 Prompt 页不能无资料生成

旧问题：普通用户进入“视频 Prompt”页时，只填写生成意图也能生成提示词，容易产生没有输入源、没有场景卡、没有素材说明的孤立 Prompt，后续无法解释来源。

新规则：

- 生成视频 Prompt 前必须满足三选一：已选场景卡、已勾选输入源、已粘贴本次资料。
- “本次资料”面向普通用户，允许粘贴产品卖点、参考素材说明、口播脚本或本地素材说明。
- 使用“本次资料”生成时，前端先自动登记为 `sop-input` 输入源，再把该输入源 ID 写入视频 Prompt 草稿。
- 没有任何可追溯资料时，主按钮禁用，并提示用户去选场景、勾输入源或粘贴本次资料。

### 4.6 素材审核必须把“通过”和“入库”合成一个普通用户动作

旧问题：素材库里有“通过审核”，SOP 步骤里又写“入素材库”，普通用户会以为还缺一个单独入库动作；详情里还直接显示提示词 ID / 运行记录 ID，像工程追踪面板。

新规则：

- 审核台主动作改为“通过并入库”，状态显示“已通过并入库 / 已入库”，把审核结论和素材库沉淀合成一个明确动作。
- 详情页保留可打开追溯入口，但不直接显示内部 ID；显示“已关联提示词，可打开查看”“已关联运行记录，可打开查看”。
- 回炉来源显示业务名称或“原素材记录”，不把 assetKey 暴露给普通用户。
- 底层仍保留 `promptDraftId`、`workflowRunId`、`assetKey` 和 `artifactRefs`，用于验收脚本、SOP 运行记录和混剪包追溯。

### 4.7 文章平台草稿包必须是可交付动作，不是路径展示

旧问题：文章生成后导出平台草稿包，界面把 `platform-drafts` 路径当作成功反馈；历史包里“复制稿”按钮实际只是打开文件。普通用户会不知道是否已经拿到可发布文案，也会误以为软件已经接管平台发布。

新规则：

- 文章主路径按 `生成正文 -> 发布检查 -> 导出平台草稿包 -> 复制发布文案 / 打开草稿包 -> 人工发布复核` 收敛。
- 导出成功卡只显示“平台草稿包已导出”和交付边界，不再把本地路径作为主要文案。
- 历史包、提示词派生交付物和 SOP 运行详情都提供“复制发布文案”真实动作，复制的是草稿包内面向目标平台的发布文案。
- “打开草稿包”只用于查看正文稿、格式指南、发布检查和追溯清单；软件不保存平台账号、不自动发布、不创建平台任务。
- 底层继续保留 `packageDir`、`manifestPath`、`platformCopyPath`、`promptDraftId`、`workflowRunId` 和 `sourceLogId`，用于文件追溯、SOP 回写和验收脚本。

### 4.8 Prompt 工作台不能把内部 ID 当作用户上下文

旧问题：Prompt 工作台的输入源、草稿和 AI 会话列表会暴露 `manual-note`、`sop-input`、短任务 ID、`PromptDraft` 等内部对象词。普通用户只需要知道资料类型、是否已解析、是否关联 SOP 和下一步可做什么。

新规则：

- 输入源卡片显示“文档 / 文本 / 图片 / 视频 / SKU 表 / 手动记录”和“品牌知识库 / 产品资料 / 评论问题 / 任务输入”等业务词，不显示内部枚举。
- 已转换文档显示“已生成可追溯转换稿”，不把本地转换稿路径作为主文案。
- 草稿、会话和来源追溯只显示“已关联 SOP”，不显示短 ID；底层 ID 仍用于跳转和验收。
- 物化 SOP / Skill、回炉沉淀和错误提示使用“提示词草稿”而不是 `PromptDraft`。

### 4.9 SOP 运行详情不能变成工程日志

旧问题：SOP 运行详情会把 `workflowKey@version`、步骤输出 ID、产物路径、`assetKey`、`sourceId` 或 raw JSON 当作主要上下文。普通用户看不出“本次用了哪些资料、现在卡在哪里、下一步去哪里、产物是否能交付”。

新规则：

- 运行详情显示“SOP vX”而不是内部 workflow key；高级维护页可以继续保留 definition JSON。
- 输入源和步骤输入 / 输出显示业务字段：用户意图、资料来源、提示词草稿、审核记录、正文稿、发布文案、混剪包和导入证据。
- 对 ID、路径和数组只显示“已关联 / 已导出 / 已登记 / 已生成 N 项”等业务状态，不把内部值作为普通用户文案。
- 产物区只显示“产物线索”和可打开的业务入口，底层 `artifactRefs` 仍用于验收脚本和本地追溯。
- 素材审核与回炉只显示“原素材记录 / 新候选素材 / 已通过并入库”，不要求普通用户理解 asset key 或日志 ID。

### 4.10 混剪交接和图片历史不能要求用户读工程记录

旧问题：混剪包导出页把 manifest JSON 当作预览，历史导入证据直接显示本地证据路径；图片历史详情直接显示生成日志 ID。剪辑人员和运营只需要确认交接清单、素材数量、导入证据和生成记录是否存在。

新规则：

- 混剪包导出页显示“交接清单预览”：目标平台、图片 / 视频 / 绿幕数量和前几条素材标题，不显示 raw JSON。
- 历史混剪包按钮使用“打开清单 / 打开 CSV / 打开导入说明 / 打开导入证据”，证据路径不作为主文案展示。
- 第三方导入表单使用“清单文件已导入或已核对”，避免让普通用户理解 manifest 实现细节。
- v2 功能说明和默认备注使用“混剪清单 / 清单文件”，本地实际文件名仍可保留 manifest 作为第三方交接格式。
- 视频素材包 SOP 的下一步动作、产物入口和绿幕文案图导轨都指向“混剪清单 / 交付清单”，不把 manifest 当作主任务。
- 图片历史详情显示“生成文件 N 个 / 生成记录已保存”，不显示生成日志 ID。
- 图片历史列表、素材候选和素材库显示“本地生成服务 / 生成服务：xxx”，不把 `local` 这类 provider 值直接当作素材上下文。
- 视频 Prompt 和成品视频导入边界说明使用“第三方任务编号”，不要求普通用户理解任务 ID。

### 4.11 知识库和图片技能入口不能默认暴露配置实现

旧问题：成型知识库入口把 `JSON` 当成普通导入格式，场景卡和提示词包直接显示内部 ID；图片技能编辑弹窗默认打开原始配置，并用 `prompts.system`、`payload` 等字段名描述用户动作。普通用户只需要导入知识库文档、查看引用和调整提示词口径。

新规则：

- 成型知识库主入口显示“导入知识库文档”，说明聚焦 DOCX / Markdown 等文档，不把 JSON 当作普通用户路径。
- 知识库生成的提示词包和场景卡显示“资料 N 份 / 已关联 SOP / 已关联提示词包”，不展示内部短 ID。
- 图片技能编辑默认进入“系统提示词”页；完整配置改名为“高级配置”，定位给内容工程师。
- 图片技能编辑的错误和说明使用“高级配置 / 参数字段 / 系统提示词”，不把 `JSON`、`payload`、`prompts.system` 等实现字段当作用户文案。

### 4.12 主链页面不能在追溯位暴露内部枚举和短 ID

旧问题：品牌 / IP 知识库、场景提示词、右侧生成记录和图片详情仍会在追溯位显示知识库 key、短任务 ID、`image / video / article` 这类用途枚举、`local` 模型值或 `ready` 状态。普通用户会把这些当成下一步任务，实际却只是工程追溯字段。

新规则：

- 品牌 / IP 知识库当前来源显示“产品型 / 个人 IP 型”和业务标题，不显示 `source:id` 组合。
- IP 场景延伸和场景提示词列表只显示“已关联同一 IP 知识库版本 / 已关联 SOP / 资料 N 份 / 图片提示词 / 视频提示词”等业务状态，不显示短 ID 或用途枚举。
- 右侧最近生成记录、图片历史详情和素材候选统一通过“本地生成服务 / 生成服务：xxx / 生成服务待配置”展示来源，不把 `local`、`blocked:*`、`fallback:*` 直接暴露给普通用户。
- SOP 高级维护仍允许内容工程师编辑结构化定义，但入口文案使用“输入字段（高级配置）/ 执行步骤（高级配置）”，校验错误说“列表格式”，不把 JSON 当作普通任务。
- Canvas 只作为 SOP 高级轻编辑视图；节点卡片显示能力类型、输出项数量和上游步骤数量，不把节点 ID、输出 key 列表当成主上下文。
