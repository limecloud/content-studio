# 布谷AI内容工厂 v2 方法论修订：文档知识库 + Agent 多轮 Prompt 生产

更新时间：2026-05-20
状态：Draft
参考来源：楚川老师课程截图、用户提供的知识库文件形态和补充说明

## 1. 核心修正

本文件只描述“知识库作为输入源”的玩法分支，不代表 v2 的全部主链。v2 的完整玩法矩阵见 [`llm-playbook.md`](./llm-playbook.md)：对标图反推、参考视频拆解、产品资料结构化、SKU 批量变体、评论痛点聚类和成功素材回炉，都可以不依赖知识库直接运行。

楚川补充后，知识库玩法必须拆成两套主链，不能继续混成“选择一个知识库再生成 Prompt”：

```text
品牌 / 产品知识库
-> 场景库
-> 提示词组
-> 图片 / 图生视频 Prompt
-> 外部生成工具或内部生成 API
-> 审核 / 素材库 / 混剪包
```

```text
个人 IP 原始素材
-> IP 知识库
-> IP 运营场景库
-> 文案 / 脚本 / 私域 / 产品化提示词
-> 场景延伸知识库
-> 内容资产和运营资产
```

上一版 v2 文档把知识库理解成“生成时选择引用片段”的 RAG 附件，这是不准确的；随后又过度走向“先结构化成数据库字段”，也不准确。

当前项目里的知识库真实形态是成型文档，例如：

```text
/Users/coso/Documents/other/谢晶_个人IP知识库v1.0_深澜智能.docx
/Users/coso/Documents/other/唯他瑞葡聚糖知识库.docx
/Users/coso/Documents/other/嘉文老师_IP知识库_v1.0.docx
```

这些文件可以转换成 Markdown，但事实源仍然是文档。Claude SDK runtime 的 AI Agent 应该带着用户意图去读取这些文档，和用户多轮调整后生成 Prompt / SOP / Skill。

楚川方法论里，知识库是内容工厂的底座，作用不是简单检索，而是帮助 Agent 判断：

- 选题判断。
- 内容方向。
- 人设和品牌表达边界。
- 关键词和话题空间。
- Prompt 模板的稳定性。
- 规模化生产的上限。

更准确的链路是：

```text
DOCX / Markdown 知识库文档
-> 转 Markdown / 建文本索引
-> Claude SDK Agent 按用户意图读取
-> Agent 提取相关观点 / 卖点 / 痛点 / 证据
-> 用户多轮调整方向
-> Prompt 草稿
-> SOP 文档化
-> Prompt 固化
-> Skill 封装
-> 批量素材生产
-> 质检 / 打标 / 回炉
-> 素材库和混剪包
```

## 2. 知识库体系的两条主链

### A. 品牌 / 产品知识库 -> 场景库 -> 提示词组

适用于产品、品牌、项目和行业解决方案。

核心不是从知识库直接生成 Prompt，而是先抽取可生产的场景库，再从场景库生成 10 组以上可复制提示词。

典型链路：

```text
唯他瑞葡聚糖知识库
-> 夏季儿童免疫相关场景库
-> UGC 手机实拍图片提示词
-> 图生视频 Prompt
-> 外部平台生成素材
```

场景库字段：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 人群 | 谁出现在场景中 | 3-6 岁儿童、妈妈、家庭成员 |
| 问题 | 场景里的真实困扰 | 夏季空调后咳嗽、泳池后揉眼、蚊虫叮咬红肿 |
| 空间 | 画面发生位置 | 客厅、儿童房、泳池边、户外公园、厨房 |
| 动作 | 人物正在做什么 | 妈妈递水、孩子揉眼、孩子挠手臂 |
| 情绪 | 画面情绪 | 温馨、担心、真实、生活化 |
| 镜头 | 画面视角 | UGC 手机实拍、自然光、轻微抓拍感 |
| 合规 | 禁止表达 | 不出现医疗承诺，不暗示治疗 |

提示词必须比“夏季儿童感冒场景”更具体，要能直接复制给外部生成器：

```text
UGC 手机实拍，客厅傍晚暖光，3 岁小男孩坐在沙发上裹着薄毯，鼻子微红轻轻咳嗽，妈妈递温水，背景可见空调出风口，真实居家光影，自然抓拍，无滤镜，细节清晰，无 AI 感
```

### B. IP 知识库

适用于个人 IP、专家、创始人、讲师、顾问。

核心不是收集几段简介，而是在一份成型文档中保存人的表达系统，让 Agent 能按任务读取。以嘉文老师 IP 知识库为例，它不是“教育品牌资料”，而是个人 IP 全面运营底座：

- AI 访谈挖掘 1-5 万字原始材料。
- 身份锚定和履历时间线。
- 价值观、立场和禁区清单。
- 语言风格、口头禅、标志性句式。
- 判断力、方法论和决策逻辑。
- 金句库。
- 观点库。
- 话题聚类。
- 人设边界。
- 内容输出模板。
- 语气、表达节奏和禁用表达。

Agent 读取后输出：

- 观点型文章。
- 口播脚本。
- 小红书笔记。
- 个人 IP 选题。
- 金句卡 / 绿幕文案图。
- 直播话术、私域回复、付费产品文案和咨询模板。

### C. 项目 AI 知识库

适用于产品、品牌、项目和行业解决方案。

核心不是把文件拆进复杂数据库，而是让文档中已经整理好的项目资料可被 Agent 稳定读取：

- 功能卖点。
- 差异化卖点。
- 场景卖点。
- 情感卖点。
- 检测报告 / 专利 / 临床文献 / 证据材料。
- 合规边界。
- 竞品对比。

输出对象：

- 电商详情页。
- 产品种草图。
- 商品短视频脚本。
- 卖点图。
- FAQ 内容。

### D. 用户痛点库 + 竞品内容库，可作为后续文档类型

适用于持续选题和素材方向判断。

来源：

- 用户评论。
- 客服问题。
- 买家秀。
- 竞品爆款内容。
- 差评。
- 搜索下拉词。
- 行业热点。

结构：

- 高频问题聚类。
- 痛点句式。
- 反对意见。
- 用户真实语言。
- 竞品内容层：讲了什么、忽略什么。
- 关键词层：哪些词反复出现。

作用：

- 决定选题方向。
- 决定内容切入角度。
- 决定标题和封面卖点。
- 帮助判断哪些内容值得规模化。

### E. 选题库和关键词五层，是 Agent 运行后的沉淀结果

关键词不是一开始必须建好的数据库表，而是 Agent 从文档和用户目标中整理出来的生产矩阵。

五层建议：

- 品牌词。
- 行业词。
- 长尾词。
- 场景词。
- 热点词。

选题矩阵：

```text
关键词 x 角度 x 人群 x 场景 x 平台
= 可批量生产的内容题库
```

示例：

```text
大健康：
症状 + 解决方案 + 人群
本地生活：
地域 + 需求 + 推荐
电商：
产品卖点 + 使用场景 + 购买顾虑
```

## 3. 知识库不是数据库，而是 Agent 可读事实源

v2 中“知识库引用”只能作为结果追溯的一部分，不能代表知识库使用的全部。更关键的是 Agent 如何读文档、如何围绕用户意图组织答案。

正确用法应分 5 层：

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 文档层 | 保存原始事实 | DOCX、Markdown、转换稿 |
| Agent 理解层 | 按用户意图读取和整理 | 找卖点、找人设口吻、找合规边界 |
| 多轮调整层 | 用户纠偏和补充 | 改内容方向、改平台风格、改输出标准 |
| 模板沉淀层 | 固化 Prompt 和输出格式 | 小红书种草模板、详情页模板 |
| 质检层 | 判断生成结果是否可用 | 是否跑题、AI 味、风格偏、合规风险 |

## 4. 素材生产的阶段划分

### Part 1：正常运营

目标：人机协同，稳定产出。

```text
Agent 读取知识库文档
-> 按用户意图组 Prompt
-> 用户多轮调整
-> 单人多线程生成图片 / 视频 Prompt
-> 人工质检
-> 入库
```

适用：

- 种草图。
- 科普图。
- SEO 图。
- 产品场景图。

### Part 2：批量自动化

目标：在无争议场景直接批量生产。

前提：

- 产品信息稳定。
- 模板固定。
- 输入输出边界清楚。
- 质量标准明确。
- 异常路径可覆盖。

适用：

- 详情页批量生成。
- 换装 / 换色 / 换背景。
- 节日海报。
- 促销主图。
- SEO 填充图。

不适用：

- 真人证言。
- 专家背书。
- 高合规风险场景。
- 需要复杂判断的新选题。

### Part 3：批量化生产和自研体系

目标：从“有素材”升级到“规模化出片”。

本软件优先覆盖：

- 脚本分段。
- 素材智能匹配。
- 参数化批量生成。
- 质检抽样。
- 绿幕文案图。
- 混剪包导出。

第三方工具覆盖：

- 视频生成平台。
- 混剪软件。
- 成片渲染。

## 5. 产品化判断标准

不是所有流程都值得产品化。只有满足以下条件，才进入 v2 SOP / Skill 化：

- 重复 10 次以上。
- 输入输出边界清晰。
- 可以无人值守或半无人值守。
- 质量标准可量化。
- 失败路径可预设。
- 从最高频、最重复、最耗人工的环节开始。

最容易踩坑：

```text
流程没跑稳就封装
-> 工程师按想象做自动化
-> 用户不断试错
-> 产品变成复杂但不好用
```

正确路径：

```text
手工跑通
-> SOP 文档化
-> Prompt 固化
-> Skill 封装
-> 平台化
```

## 6. 给工程实现的约束

1. **知识库先做文档导入和 Markdown 转换，不先做复杂数据库。**
   - 当前优先是让 Agent 能完整读取成型知识库文档。
   - 结构化摘要、选题矩阵和 Prompt 模板是多轮运行后的沉淀结果。
   - 后续需要语义召回时再补向量检索。

2. **素材打标先依赖文件和 manifest。**
   - 图片写 XMP 或 sidecar JSON。
   - 视频写 JSON metadata。
   - 同步到素材库索引。

3. **先跑通一个平台。**
   - 建议先用公众号或小红书验证完整链路。
   - 跑通后再扩展抖音、B 站、电商详情页。

4. **AI 不替代所有人工判断。**
   - 选题、人设边界、合规、最终交付必须有人审。
   - 批量自动化只适用于规则明确的无争议场景。

5. **工程师交付的是 Agent 可稳定执行的产品化流程，不是炫技画布。**
   - canvas 可以辅助查看流程。
   - 但真正的交付物是稳定 SOP、Prompt 模板、Skill 和可复用素材包。
