## 一、核心信息提炼法

### 电梯测试（30秒法则）

在写任何一页PPT之前，必须先通过电梯测试：

```
想象你在电梯里遇到目标受众，只有30秒时间。
你会说什么？

公式：[谁] + [面临什么问题] + [我们的方案] + [能带来什么价值]

示例：
❌ "我们是一家AI公司，有很多产品..."（没重点）
✅ "中小企业每年花50万在客服上，我们的AI客服能砍掉70%成本"（清晰有力）
```

### 一句话核心信息模板

| 场景 | 模板 | 示例 |
|------|------|------|
| 说服型 | [方案]能帮[受众]解决[痛点]，实现[价值] | AI客服能帮中小企业降低70%客服成本 |
| 汇报型 | [时间段]完成了[核心成果]，关键突破是[亮点] | Q3超额完成150%目标，核心是新渠道打通 |
| 教学型 | 学完后你能掌握[能力]，解决[问题] | 掌握数据分析三板斧，告别拍脑袋决策 |
| 展示型 | [产品/项目]的核心价值是[独特优势] | 新CRM系统让销售转化率提升40% |

## 二、四大叙事框架

### 框架1：SCQA（最通用，首选）

```
S - Situation（情景）：大家共知的背景事实
C - Complication（冲突）：出了什么问题/变化
Q - Question（问题）：所以我们该怎么办？
A - Answer（回答）：这就是我们的方案/成果

适用：几乎所有场景，尤其是说服型和提案型
页数分配：S占10% | C占15% | Q隐含 | A占75%
```

**SCQA实操示例（融资BP）**：
```
S：企业客服市场规模5000亿，年增长20%
C：但80%中小企业仍依赖人工客服，成本高、效率低、体验差
Q：（隐含：如何让中小企业用上智能客服？）
A：我们的AI客服SaaS——3分钟部署、成本降70%、满意度升30%
   → 产品演示 → 市场策略 → 团队 → 财务 → 融资需求
```

### 框架2：时间线叙事

```
过去 → 现在 → 未来

适用：工作汇报、项目总结、企业发展历程
结构：
├─ 过去（20%）：起点在哪、做了什么
├─ 现在（50%）：成果、数据、关键突破
└─ 未来（30%）：计划、目标、资源需求

关键：过去要简洁，重心放现在的成果上，未来要有具体行动计划
```

### 框架3：对比叙事

```
Before → After / 现状 → 愿景 / 问题 → 方案

适用：方案提案、产品发布、变革推动
结构：
├─ Before/现状（30%）：痛点可视化，让受众"感同身受"
├─ 转折点（10%）：为什么现在必须改变
└─ After/方案（60%）：新世界是什么样的

关键：Before的痛点要具体到场景和数字，不要抽象
```

### 框架4：模块化叙事

```
总论 → 分论1 → 分论2 → 分论3 → 总结

适用：培训课件、知识分享、多主题汇报
结构：
├─ 总论（10%）：今天讲什么、为什么重要
├─ 分论×N（70%）：每个模块独立完整
└─ 总结（20%）：串联、总结、行动项

关键：模块之间要有过渡，不是简单拼接
```

### 框架选择决策树

```
你的核心目标是什么？
│
├─ 说服对方接受一个方案 → SCQA
├─ 展示一段时间的成果 → 时间线
├─ 推动一个改变/升级 → 对比
├─ 传授多个知识点 → 模块化
│
└─ 不确定？→ 默认用 SCQA（最安全最通用）
```

## 三、金字塔原理在PPT中的应用

### 核心法则：结论先行

```
金字塔结构：

         [核心结论]              ← 第一页就亮出来
        /    |     \
   [论点1] [论点2] [论点3]      ← 三个支撑柱
   /  \    /  \    /  \
 [据] [据] [据] [据] [据] [据]  ← 数据/案例/逻辑

PPT映射：
├─ 核心结论 → 封面标题或开篇总览页
├─ 论点 → 章节页（每个论点是一个章节）
└─ 论据 → 内容页（数据/图表/案例）
```

### MECE原则（互斥且穷尽）

```
拆分论点时确保：
├─ 互斥（Mutually Exclusive）：论点之间不重叠
├─ 穷尽（Collectively Exhaustive）：论点覆盖完整

❌ 不好的拆分：
"我们的优势是：技术强、产品好、研发投入大"
（"技术强"和"研发投入大"有重叠）

✅ 好的拆分：
"我们的优势：产品（做什么）、团队（谁在做）、市场（给谁做）"
（三个维度互不重叠，覆盖完整）
```

## 四、情绪弧线设计

### 为什么PPT需要情绪弧线？

```
人类不记信息，记感受。
一个让人"有感觉"的PPT，比"信息全面"的PPT有效10倍。
```

### 四种情绪弧线模型

```
模型1：渐进高潮型（适合路演/提案）
情绪 ▲
     │        ╱─── 高潮（核心方案/成果）
     │      ╱
     │    ╱
     │──╱ 铺垫
     └──────────────────▶ 时间

模型2：先抑后扬型（适合述职/转型方案）
情绪 ▲
     │╲              ╱── 成果
     │  ╲    ╱╲    ╱
     │    ╲╱    ╲╱ 挑战与突破
     └──────────────────▶ 时间

模型3：平稳递进型（适合培训/知识分享）
情绪 ▲
     │          ╱─
     │      ╱──╱
     │  ╱──╱
     │╱ 每个模块稳步提升
     └──────────────────▶ 时间

模型4：悬念揭晓型（适合产品发布）
情绪 ▲
     │                  │ 揭晓！
     │    ？  ？  ？    │
     │  ╱ ╲╱ ╲╱ ╲   │
     │╱              ╲ │╱
     └──────────────────▶ 时间
```

### 情绪节拍器（Pacing）

```
每5-7页需要一个"情绪转折点"：
├─ 震撼数据（"行业已经变了"）
├─ 真实故事（客户案例/用户故事）
├─ 视觉冲击（全屏图片/大数字）
├─ 互动环节（提问/投票）
├─ 过渡金句（承上启下的一句话）

❌ 禁止：连续5页以上相同节奏的文字+图表页
```

## 五、受众分析矩阵

### 四象限受众模型

```
              了解你的领域
                  ↑
     【内行友军】  │  【内行审视者】
     直奔干货     │  准备被挑战
     省略基础     │  数据要精准
    ───────────┼───────────→ 对你友好/质疑
     【外行支持者】│  【外行质疑者】
     讲清价值     │  降低门槛
     用类比       │  用故事打动
                  │
```

### 受众适配规则

| 受众类型 | 语言风格 | 内容深度 | 说服策略 |
|---------|---------|---------|---------|
| 投资人 | 商业语言、数据驱动 | 宏观+关键细节 | 市场规模→增长潜力→退出路径 |
| 老板/高管 | 结果导向、简洁 | 高度概括 | 成果→ROI→下一步行动 |
| 同事/团队 | 专业但友好 | 可以深入 | 逻辑→方法→可复用 |
| 客户/外部 | 通俗易懂、场景化 | 适中 | 痛点共鸣→方案价值→成功案例 |
| 学员/新人 | 简单、多类比 | 由浅入深 | 为什么重要→怎么做→练习巩固 |

## 六、标题写法与内容约束

### 标题写法铁律

```
好标题 = 让人一眼知道这页在说什么 + 激发好奇心

四种高效标题句式：

1. 数字开头：用数据制造冲击力
   ✅ "3个月，200万用户"
   ✅ "47%的增长从何而来"
   ❌ "用户增长情况"

2. 动词开头：用行动感驱动注意力
   ✅ "打通全渠道，释放数据价值"
   ✅ "重新定义客服体验"
   ❌ "全渠道解决方案"

3. 结论式：直接亮出这一页的核心观点
   ✅ "内容营销CAC仅为投放的1/3"
   ✅ "市场空间远超预期"
   ❌ "市场分析"

4. 问题式：用问题激发思考（适合过渡页/教学）
   ✅ "为什么80%的企业转型失败？"
   ✅ "你的客户真正在乎什么？"
   ❌ "关于数字化转型"

标题通用规则：
├─ 长度≤12个汉字
├─ 避免"关于XX""XX介绍""XX概述"等无信息量标题
├─ 标题本身就是结论，不是类别标签
```

### 正文内容约束（30字/15字法则）

```
单页约束：
├─ 正文总字数≤30字（标题除外）
├─ 每个要点≤15字
├─ 要点数量≤5个（推荐3个）
├─ 超过就拆页或转化为视觉元素

文字精简检查法：
├─ 删掉所有形容词，看意思是否改变 → 不变就删
├─ 删掉"的""了""着"等虚词，看是否更有力
├─ 能用数字表达就不用文字
├─ 能用图表/图标表达就不用文字

❌ "我们的产品具有非常领先的技术优势和极高的性价比"
✅ "技术领先 | 成本降70%"
```

## 七、大纲构建方法

### 三步成纲法

```
Step 1：便签法（发散）
把所有想说的点写在"虚拟便签"上，不分先后，不管逻辑

Step 2：归类法（收敛）
按金字塔原理把便签归入3-5个大类，每类就是一个章节

Step 3：排序法（定序）
按叙事框架排列章节顺序，检查逻辑递进关系
```

### 每页大纲标准格式

```
PX [页面类型] | 布局建议：[类型]
  → 标题：[页面标题，≤12字]
  → 核心观点：[这一页想传递的一个信息]
  → 支撑方式：[数据/图表/案例/对比/引用]
  → 视觉元素：[图表类型/全屏图/图标组]
  → 演讲时长：[X分钟]
```

### 页面类型清单

| 类型 | 作用 | 频率 |
|------|------|------|
| 封面页 | 第一印象、定调 | 1次 |
| 目录/导航页 | 建立预期、结构感 | 1-2次 |
| 章节过渡页 | 节奏切换、承上启下 | 每章节1次 |
| 核心内容页 | 传递信息 | 主体 |
| 数据展示页 | 量化论证 | 按需 |
| 全屏视觉页 | 情绪转折、视觉休息 | 每5-7页1次 |
| 引用/金句页 | 增强说服力 | 0-2次 |
| 总结页 | 回顾核心信息 | 1次 |
| CTA页 | 明确下一步行动 | 1次 |
| 致谢/联系页 | 收束 | 1次 |

## 八、过渡与连接设计

### 页间过渡三种方式

```
1. 逻辑过渡：上一页的结论是下一页的前提
   "既然市场规模够大，那我们的产品是什么？"

2. 问题过渡：上一页制造问题，下一页回答
   "面对这些挑战，该怎么办？"

3. 时间过渡：按时间线自然推进
   "完成了基础建设，接下来看Q4计划"
```

### 章节过渡页设计

```
作用：让观众知道"我们到哪了"

格式选项：
├─ 大字章节名 + 一句话预告
├─ 进度条/导航栏高亮当前章节
├─ 上一章节一句话总结 + 下一章节引入
└─ 全屏视觉 + 章节标题
```

## 九、数据可视化选型

### 数据→图表匹配表

| 你想表达什么 | 推荐图表 | 避免使用 |
|------------|---------|---------|
| 趋势变化 | 折线图、面积图 | 饼图 |
| 比较大小 | 柱状图、条形图 | 折线图 |
| 占比构成 | 饼图、堆叠柱状图 | 折线图 |
| 分布情况 | 散点图、直方图 | 饼图 |
| 关系关联 | 散点图、气泡图 | 柱状图 |
| 流程/层级 | 流程图、树状图 | 饼图 |
| 地理分布 | 地图 | 柱状图 |

### 数据展示铁律

```
1. 标题即结论：图表标题不是"Q3收入"，而是"Q3收入增长47%"
2. 高亮关键值：用颜色/粗体突出最重要的数字
3. 删减噪音：去掉不支持论点的数据
4. So What：每个数据后面必须跟一句解读
5. 数据来源：右下角标注数据来源
```
