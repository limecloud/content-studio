## 五阶段全流程

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ S1 诊断  │──▶│ S2 构思  │──▶│ S3 内容  │──▶│ S4 设计  │──▶│ S5 交付  │
│ 需求定位  │   │ 故事线   │   │ 逐页撰写  │   │ 版式落地  │   │ 检查上线  │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
   ↓              ↓              ↓              ↓              ↓
 明确受众      SCQA框架      场景引擎      设计系统      交付清单
 确定目标      金字塔原理     内容填充      配色排版      演讲备注
 选择引擎      情绪弧线      数据可视化     视觉层次      QA检查
```

### S1 诊断阶段（主控执行，无需加载模块）

必问六要素（需求诊断核心）：
| 要素 | 问什么 | 影响 |
|------|--------|------|
| 场景类型 | 路演/汇报/提案/培训/发布？ | 决定引擎选择 |
| 目标受众 | 投资人/老板/客户/学员/同事？ | 决定深度和说服策略 |
| 核心目标 | 说服/汇报/教学/展示？ | 决定故事线框架 |
| 时间限制 | 5分钟/15分钟/30分钟/1小时？ | 决定页数和信息密度 |
| 风格偏好 | 商务/科技/极简/文艺/品牌色？ | 决定配色和版式 |
| 素材现状 | 从零开始/有文档/有旧PPT改？ | 决定工作模式 |

受众-目标矩阵（快速判断）：
```
受众了解度 × 你的目标 → 策略
├─ 不了解 × 要说服 → 先建共识再推方案（E01/E03）
├─ 了解 × 要说服 → 直击差异化价值（E03）
├─ 不了解 × 要教学 → 从基础到进阶递进（E04）
├─ 了解 × 要汇报 → 跳过背景直奔成果（E02）
└─ 混合受众 → 分层叙事（执行摘要+详细内容）
```

### S2 构思阶段
> 加载 `shared/storytelling-framework.md`

核心任务：
1. 提炼一句话核心信息（如果只能记住一句话，是什么？）
2. 选择叙事框架（SCQA / 时间线 / 对比 / 问题解决）
3. 设计情绪弧线（起→承→转→合）
4. 输出PPT大纲（每页标题+核心观点+支撑方式）

### S3 内容阶段
> 加载对应场景引擎 `engines/eXX-*.md`

核心任务：
1. 按引擎模板填充每页内容
2. 每页一个核心观点（ONE Slide ONE Point）
3. 数据可视化选型（图表类型匹配数据故事）
4. 过渡页和节奏控制

### S4 设计阶段
> 加载 `shared/slide-design-system.md` + `shared/color-library.md` + 调用 pptx 公共技能执行

核心任务：
1. 选择配色方案（从配色库40套中按行业×情绪×趋势匹配）
2. 确定字体组合和层次
3. 版式系统（每页布局类型分配）
4. 视觉元素（图标/图片/图表）
5. 数据可视化配色（使用配色库中的色阶和分类色板）

### S5 交付阶段
> 加载 `shared/delivery-checklist.md`

核心任务：
1. 内容自检（逻辑通顺、数据准确、无错别字）
2. 设计自检（对齐一致、配色统一、留白充分）
3. 演讲备注编写
4. 导出与兼容性检查

## 内审系统（强制执行）

### 第一层：逻辑完整性检测
```
🔍 检测项：
├─ 是否有明确的核心信息？（一句话能说清吗？）
├─ 叙事框架是否完整？（开头→展开→收束）
├─ 每页是否只有一个核心观点？
├─ 页与页之间是否有逻辑递进？
└─ 是否有明确的行动号召（CTA）？
```

### 第二层：内容质量检测
```
🔍 检测项：
├─ 数据是否有来源标注？
├─ 单页正文是否≤30字（标题除外）？
├─ 每个要点是否≤15字？
├─ 视觉元素占比是否≥60%（6:4图文比）？
├─ 标题是否用动词开头或数字开头？
├─ 图表类型是否匹配数据故事？
├─ 是否有"So What"——每个数据后的洞察结论？
├─ 是否消除了行业黑话和自嗨表达？
└─ 换位思考：观众看完能记住哪三个点？
```

### 第三层：设计规范检测
```
🔍 检测项：
├─ 配色是否全局统一且≤3色？
├─ 字体是否≤2种？层次是否清晰（标题>正文>注释）？
├─ 图文比是否≥6:4（视觉元素占比≥60%）？
├─ 边距是否留出8%安全区？
├─ 所有元素是否网格对齐？
├─ 每页是否有视觉焦点（图/表/数字/图标）？
├─ 是否避免了连续3页相同版式？
├─ 留白是否充分（填充率≤70%）？
└─ 能否用一句话串联所有页的逻辑线？
```

### 自审报告格式
```markdown
### 🔍 PPT自审报告
- 逻辑完整性：✅通过 / ⚠️[问题]
- 内容质量：✅通过 / ⚠️[问题]
- 设计规范：✅通过 / ⚠️[问题]
- 总页数：[X]页 | 预计演讲时长：[X]分钟
- 信息密度评估：[适中/偏高/偏低]
- 一句话串联测试：[能否用一句话串联所有页的逻辑线？]
- 三点记忆测试：[观众看完最可能记住哪三个点？]
- 综合评分：[X]/100
```

## 工作模式

### 模式A：完整制作（默认）
```
1. S1诊断 → 明确受众/目标/约束
2. 路由匹配 → 加载场景引擎 + storytelling
3. S2构思 → 输出PPT大纲（确认后继续）
4. S3内容 → 按引擎模板逐页撰写
5. S4设计 → 加载design-system → 调用pptx技能生成
6. S5交付 → 加载delivery-checklist → 自审 → 输出
```

### 模式B：仅构思大纲
```
1. S1诊断 → 明确需求
2. 加载 storytelling-framework
3. 输出PPT大纲（每页：标题+核心观点+支撑方式+版式建议）
```

### 模式C：仅优化设计
```
1. 读取现有PPT内容
2. 加载 slide-design-system
3. 输出设计优化方案 → 调用pptx技能执行
```

### 模式D：仅内容填充
```
1. 用户提供大纲/提纲
2. 匹配场景引擎
3. 按引擎模板填充内容 → 输出逐页文案
```

### 模式E：生成演讲稿全文
```
1. 基于已完成的PPT逐页脚本
2. 将演讲备注扩展为完整口播稿
3. 标注停顿/语气/互动节奏
4. 输出可直接朗读的演讲全文
```

### 模式F：设计工具导入指令
```
1. 基于已完成的逐页脚本+视觉规范
2. 输出可直接用于AI设计工具的描述
3. 支持：Gamma / Beautiful.ai / Canva / pptx公共技能
```

## 铁律（10条军规）

| # | 铁律 | 说明 |
|---|------|------|
| 1 | **一页一核心** | 每页只传递一个关键信息，观众只记住一个点 |
| 2 | **30字上限** | 单页文字不超过30字（标题除外），超过就拆页或图形化 |
| 3 | **三色原则** | 全篇配色不超过3种（主色60%+辅色30%+强调色10%） |
| 4 | **两字体原则** | 中英文各一种字体，全局最多2种，绝不超过3种 |
| 5 | **6:4图文比** | 视觉元素占比≥60%，每页必须有视觉焦点，禁止纯文字页 |
| 6 | **对齐强迫症** | 所有元素必须网格对齐，误差≤2px，用参考线检查 |
| 7 | **数据有结论** | 每个图表必须标注"So What"——关键数字+一句话洞察 |
| 8 | **动画要克制** | 只用淡入/淡出，禁止旋转/弹跳/3D等花哨特效 |
| 9 | **留白是设计** | 页面填充率≤70%，空白不是浪费，是呼吸感 |
| 10 | **结尾有行动** | 最后一页必须有明确的CTA（行动号召），不是"谢谢" |
