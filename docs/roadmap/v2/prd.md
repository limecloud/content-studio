# 布谷AI内容工厂 v2 PRD：大模型玩法驱动的内容素材工厂

更新时间：2026-05-21
状态：Archived / Retired SOP Sections

## 0. 当前状态说明

本文保留 2026-05 早期 v2 产品推演，里面关于 SOP 工作流、`WorkflowDefinition`、`WorkflowRun`、表单执行页和 Canvas 工作流维护的章节已经退役，不再作为客户端当前实现契约。

当前客户端收敛方向：

- `current`：成型知识库、品牌 / IP 知识库、场景库、Prompt 工作台、图片 / 视频 Prompt / 文章 / 素材库、内容制造批次、审核 / 生产交接和 `run-trace` 历史追溯。
- `compat`：旧 `workflowRunId`、`workflow-runs.json`、`sop-input` 和旧 `workflow-run` kind 只用于旧工作区追溯或向 `run-trace` 归一化。
- `dead`：SOP 工作流客户端模块、`WorkflowStore`、`WorkflowEngine`、`WorkflowFeatureModule`、工作流定义维护和 Canvas 编排不再恢复。

后续 PRD 修订应把“跑通后沉淀”的目标表达为 Prompt / 场景卡 / Skill 草稿 / 内容制造批次模板，而不是新增客户端 SOP 运行时。

## 1. 背景

v1 已经把内容工厂从单一图片生成工具扩展成包含知识库、提示词包、场景卡、文章、图片、视频队列和素材库的桌面客户端工作台。用户后续补充的业务诉求表明：未来会有很多类似 SOP，例如小红书种草图、公众号长图文、抖音口播脚本、B 站深度稿、详情页图、视频素材包和绿幕文案图。

v2 的产品形态必须继续是 **客户端优先**：用户在本机选择工作区，文件、生成记录、素材和配置优先写入本地 `.content-studio/`；模型生成服务、RunningHub、混剪软件等是外部能力接入，不把产品改造成 SaaS 后台、租户系统或云协作平台。

但知识库的真实形态不是数据库表，而是用户已经整理好的 DOCX / Markdown 文档，例如个人 IP 知识库和产品项目知识库。v2 的一个关键目标是让随包 Lime App Server / RuntimeCore 的 AI Agent 能带着用户意图读取这些文档，经过多轮追问、纠偏和调整后，生成可复用 Prompt、Skill 草稿和内容制造批次模板。

同时，很多高价值玩法并不从知识库开始。例如上传小红书参考素材拆解构图和风格、拆解爆款视频节奏、把 SKU 表批量转成详情页素材、从评论里聚类痛点。v2 的主链应是“输入源 -> 大模型理解 / 反推 / 改写 / 生成 / 质检 -> Prompt / SOP / Skill 沉淀 -> 素材生产”，而不是单一知识库链路。

楚川补充后需要进一步修正：品牌 / 产品知识库不能直接跳到 Prompt，而应先形成 **场景库**，再从场景库生成可复制的图片 / 图生视频提示词。个人 IP 知识库也不是品牌知识库的一个字段，而是用于个人 IP 全面运营的独立体系，至少包含身份锚定、价值观立场、声音语言、判断方法、内容素材和创作引擎六层，并继续延伸出口播、文案、私域、产品化等场景知识库。

## 2. 用户问题

| 用户问题 | 影响 |
| --- | --- |
| 业务方会不断新增平台 SOP。 | 每个 SOP 都写页面会造成重复代码和维护困难。 |
| 内容生产既可能读取知识库，也可能直接参考图片、视频、竞品和产品资料。 | 单一路径会覆盖不了真实玩法。 |
| 品牌 / 产品知识库直接生成 Prompt 会过粗。 | 缺少场景库会导致提示词不够真实、不够具体，无法稳定生成 UGC 感画面。 |
| IP 知识库和品牌知识库被混用。 | 个人 IP 运营需要完整人设、观点、语言、方法论和内容引擎，不能只当素材附件。 |
| 品牌、人设和产品知识库文档需要被 Agent 充分读取。 | 只做关键词检索会丢失上下文、方法论和表达风格。 |
| 无知识库的对标扒图和视频拆解也很高频。 | 如果强制先建知识库，会拖慢素材生产。 |
| Prompt 需要多轮调整，不是一轮生成。 | 用户意图、平台方向、风格和合规边界需要反复纠偏。 |
| 图片、文案、视频素材任务之间依赖复杂。 | 需要记录 Agent 会话、Prompt 草稿、生成任务和审核结果。 |
| 视频 API 成本不稳定。 | 需要清晰区分软件内 API 生成和人工复制 Prompt 到外部平台。 |
| 视频最终会交给第三方混剪软件。 | 自研剪辑优先级低，系统应该先导出可混剪素材包。 |
| 生成结果需要筛选和打标。 | 没有素材状态和标签会导致复用困难。 |
| 运营不一定懂工作流节点。 | canvas 和 SOP 表单都不能成为当前入口，需要把复杂链路投影成 Prompt、素材、审核、交接和运行追溯。 |
| v2 原型容易偏成 SaaS / 后台产品。 | 必须保留现有客户端模块和三栏工作台，把新能力作为渐进增强挂入图片、视频、文案、知识库和素材库。 |

## 3. 产品目标

1. 支持统一输入源：DOCX / Markdown 知识库、参考图、参考视频、产品资料、SKU 表、竞品内容、用户评论和历史成功素材。
2. 支持 DOCX / Markdown 知识库导入、转换和原文追溯。
3. 支持品牌 / 产品知识库抽取场景库，再从场景库生成可复制图片 / 图生视频提示词。
4. 支持个人 IP 知识库六层结构：身份锚定、价值观立场、声音语言、判断方法、内容素材、创作引擎。
5. 支持 Lime App Server Agent 带着用户意图读取知识库文档，并进行多轮 Prompt 调整。
6. 支持无知识库的素材拆解 Prompt、参考视频拆解和产品资料结构化。
7. 支持把确认过的 Prompt 草稿沉淀为 Prompt Pack、Skill 草稿或内容制造批次模板。
8. 支持内容制造批次和运行追溯：输入源、Agent 会话、Prompt 版本、模型、产物、错误、审核和交付物可追溯。
9. 支持旧 `workflowRunId` / `workflow-runs.json` 兼容读取，但新能力不再新增 SOP 运行时。
10. 支持平台化内容生产：小红书、公众号、抖音 / 视频号、知乎 / B 站、电商详情页。
11. 支持素材类型统一：文案、标题、图片、视频 Prompt、可选导入视频、绿幕文案图、混剪清单。
12. 支持视频两条路径：内部 API 生成，以及人工复制视频 Prompt 到 RunningHub / 第三方平台。
13. 支持素材库打标：平台、类型、主题、状态、来源、运行追溯、输入源、Prompt 版本。
14. 支持人工审核：通过、驳回、重生成、入库、导出。
15. 支持混剪素材包导出：文件夹、JSON 清单文件、CSV 简表、素材命名和标签。
16. 不恢复 canvas / SOP 表单作为客户端入口；复杂依赖只允许先进入内容制造批次和 Agent runtime 契约，再按需做只读可视化。
17. 保留现有图片生成入口，并升级为“Prompt / 场景库 / 参考图 / 产品图 -> 图片候选 -> 审核入库”的主流程。
18. 保留现有视频模块，但调整定位：优先做视频拆解、视频脚本、视频 Prompt、成品视频可选导入和混剪包导出；内部视频 API 生成作为可选高成本能力。

## 4.1 客户端边界

v2 不按 SaaS 设计：

- 不设计租户、团队空间、组织权限、在线协作素材库和服务端计费后台。
- 不要求用户把知识库、素材和视频上传到布谷云端才能使用。
- 不把服务端数据库作为事实源；本地工作区文件是第一事实源。
- 不把外部视频平台流程纳入软件任务状态；软件只保存 Prompt、复制记录和用户手动导入的成品文件。

v2 要保留并增强当前客户端：

| 当前模块 | v2 保留方式 | 原因 |
| --- | --- | --- |
| 图片生成 | 保留为一级入口，并接入场景库、提示词组、参考图反推和质检。 | 当前用户能直接得到素材，是最有即时价值的能力。 |
| 视频生成 / 拆解 | 保留为一级入口，但主路径从“内部生成视频”调整为“拆解 / 脚本 / 视频 Prompt / 可选导入”。 | 内部视频 API 成本高，Prompt 和素材包更符合当前成本结构。 |
| 文章生成 | 保留，并升级为知识库 Agent 文章和平台排版检查。 | IP 内容和品牌长文仍需要。 |
| 成型知识库 | 保留，并拆分品牌 / 产品知识库与 IP 知识库。 | 避免泛化知识库造成链路混乱。 |
| 素材库 | 保留，并升级为资产库和运行追溯。 | 支撑复用、回炉和混剪包导出。 |
| skills 管理 | 保留，并扩展为 SkillDefinition / SkillRun 管理。 | Prompt、成功素材和方法论需要沉淀。 |

| UC-09 | 可选导入第三方视频 | 短视频运营 | 第三方平台已生成视频文件 | 用户手动导入视频文件；选择关联原 Prompt；系统入库并打标签。 | video-clip artifact | 不要求绑定外部任务 ID；只追溯本软件内 Prompt 和导入文件。 |
| UC-10 | 绿幕文案图生成 | 短视频运营 | 已有脚本或卖点列表 | 抽标题卡、卖点卡、金句卡、CTA 卡；生成绿幕 / 透明 / 纯色背景图。 | 绿幕图 artifact | 文案过长时提示拆分，不强行压缩到不可读。 |
| UC-11 | 审核与入库 | 审核人员 | 有待审 artifact | 查看预览、来源、Prompt、参数和质检；通过、驳回或重生成。 | 审核状态、标签、原因 | 驳回必须保留原因和原产物。 |
| UC-12 | 混剪素材包导出 | 剪辑人员 | 有通过审核的素材 | 选择素材；导出文件夹、图片、绿幕图、可选视频文件和混剪清单。 | 混剪素材包 | v2 不做时间线剪辑和成片渲染。 |
| UC-13 | 方法论沉淀 | 内容工程师 | 某玩法已手工跑通多次 | 从 Prompt、输入源、审核结论和交付记录生成 Skill 草稿或内容制造批次模板；人工确认；保存版本。 | Skill 草稿 / 批次模板 | 草案默认不可直接上线，必须人工确认。 |
| UC-14 | 成功素材回炉 | 品牌负责人 / 内容工程师 | 素材已通过审核 | 反推 Prompt、标签和质量原因；生成模板或 Skill 草稿。 | Prompt 模板 / Skill 草稿 | 只沉淀本方成功素材，不复制竞品可识别元素。 |
| UC-15 | 品牌场景库生成 | 品牌运营 / 短视频运营 | 已导入品牌 / 产品知识库 | Agent 读取知识库；按季节、人群、问题、空间和情绪抽取场景；用户确认；保存场景卡。 | SceneLibrary / SceneCard | 缺少事实时要求用户补充，不编造功效和医学结论。 |
| UC-16 | 场景提示词生成 | 短视频运营 | 已有场景卡 | 选择 1-N 个场景；生成 10 组 UGC 手机实拍图片 / 图生视频提示词；用户复制到外部工具。 | PromptGroup / PromptDraft | 提示词必须避免 AI 感、医疗化承诺和摆拍广告感。 |
| UC-17 | IP 知识库构建 | IP 主理人 / 内容工程师 | 已上传访谈稿、课程大纲或产品资料 | Agent 读取材料；生成身份、价值观、语言、方法论、素材和创作引擎六层；用户补齐缺口；导出 DOCX / Markdown。 | IpKnowledgeBase | 不把 IP 知识库混入品牌知识库；缺失层级要标记待补充。 |
| UC-18 | IP 场景延伸库生成 | IP 运营 | 已有 IP 知识库 | 选择口播、文案、私域、产品化或咨询回复场景；生成对应知识库和提示词；人工确认。 | IpScenarioKnowledgeBase | 必须引用同一 IP 知识库版本，不允许改写成人设漂移。 |

### 4.4 端到端主路径

| 路径 | 主流程 | 完成定义 |
| --- | --- | --- |
| 无知识库小红书扒图 | 参考图 + 产品资料 -> 反推 Prompt -> 生成图片 -> 质检 -> 审核 -> 入库 | 不依赖知识库，产物可追溯参考图和 Prompt。 |
| 品牌知识库场景提示词 | 品牌 / 产品知识库 -> 场景库 -> 10 组 UGC 图片 / 图生视频提示词 -> 外部生成 -> 可选导入素材 | 场景和提示词可追溯知识库来源，提示词可直接复制。 |
| IP 知识库完整运营 | 原始素材 -> 六层 IP 知识库 -> IP 运营场景库 -> 文案 / 脚本 / 私域 / 产品化内容 | 所有场景延伸库都关联同一 IP 知识库版本。 |
| 知识库 IP 内容 | IP 知识库 DOCX / Markdown -> Agent 多轮 -> Prompt -> 文案 / 脚本 -> 发布检查 -> 导出 | 文案可追溯文档来源和 Agent 会话。 |
| 产品商业素材 | 产品知识库 / brief + 产品图 + 参考图 -> Prompt -> 图片 / 文案 -> 审核 -> 素材包 | 同一产品能沉淀可复用 Prompt 和标签。 |
| 视频 Prompt 外部生成 | 图片素材 + 卖点 -> 视频 Prompt -> 人工复制到第三方 -> 可选导入成品视频 | 软件只管理 Prompt 和导入文件，不管理外部任务。 |
| 混剪素材包 | 已通过图片 / 绿幕图 / 可选视频 -> 导出文件夹和 manifest | 第三方混剪软件可读取素材和元数据。 |

## 5. 功能范围

### 5.1 文档知识库、场景库和 Agent Prompt 生成

知识库文件是事实源，v2 需要优先支持：

- 导入 DOCX / Markdown。
- 转换为 Markdown / 纯文本索引。
- 保留原文件路径、转换稿路径和章节位置。
- Lime App Server Agent 可读取知识库全文或相关章节。
- 品牌 / 产品知识库先抽取场景库，例如“夏季儿童免疫相关 UGC 场景”。
- 从场景库生成 10 组可直接复制的图片 / 图生视频提示词。
- IP 知识库按六层结构展示完整度，并支撑后续运营内容。
- 用户输入意图，例如“基于嘉文老师 IP 知识库生成视频号口播逐字稿”。
- Agent 多轮追问和调整，例如平台、风格、目标人群、禁用表达、输出格式。
- 生成 Prompt 草稿。
- 用户确认后沉淀为 Prompt Pack、Skill 或内容制造批次模板。

示例知识库：

```text
谢晶_个人IP知识库v1.0_深澜智能.docx
唯他瑞葡聚糖知识库.docx
嘉文老师_IP知识库_v1.0.docx
```

知识库可以在 Agent 会话中临时抽取：

- 人设口吻。
- 品牌调性。
- 产品卖点。
- 案例。
- FAQ。
- 合规边界。
- 适合平台。

但这些结构不是必须预先入库，只有高频复用内容才需要沉淀为模板或 Skill。

品牌 / 产品知识库与 IP 知识库的产物不同：

| 知识库类型 | 中间层 | 下游产物 |
| --- | --- | --- |
| 品牌 / 产品知识库 | 场景库、卖点卡、合规边界 | 图片 Prompt、图生视频 Prompt、详情页素材、种草图 |
| IP 知识库 | IP 运营场景库、口吻规则、内容素材库 | 口播稿、朋友圈文案、公众号长文、私域回复、付费产品文案 |

### 5.2 大模型玩法工作台

v2 需要把高频玩法产品化，而不是只做固定表单：

- 文档知识库 Agent：读 DOCX / Markdown，生成 Prompt、文案、脚本。
- 素材拆解：上传参考图和产品资料，拆解构图、光线、文案区域并生成图片 Prompt。
- 对标视频拆解：上传参考视频，拆镜头、节奏、字幕结构和脚本。
- 产品资料结构化：把手填 brief、SKU 表、卖点表转成生产变量。
- 用户痛点聚类：从评论、差评和客服问题中生成选题矩阵。
- 批量变体：围绕稳定 Prompt 模板批量换背景、场景、SKU 和平台。
- 质检评分：检查事实、合规、产品一致性、文字可读性和 AI 味。
- 成功素材回炉：从通过审核的素材反推 Prompt 和标签，沉淀为模板或 Skill。

### 5.3 已退役历史方案：SOP 工作流

本节保留早期方案样例，不再作为当前客户端功能范围。当前客户端不恢复 `WorkflowStore`、`WorkflowEngine`、`WorkflowFeatureModule`、SOP 表单执行或 Canvas 工作流维护。

每个 SOP 至少包含：

- 名称、平台、目标产物。
- 需要的输入源：知识库文档、参考图、参考视频、产品资料、SKU 表、竞品内容等。
- 输入字段。
- 步骤列表。
- 每步调用的能力类型。
- 产物入库规则。
- 审核规则。
- 导出规则。

示例：

```text
小红书种草图 SOP
输入：产品图、参考图、产品资料、目标人群
步骤：反推参考图风格 -> 结构化产品资料 -> 生成 Prompt 草稿 -> 用户多轮调整 -> 生成 4 张图 -> 质检 -> 人审 -> 入库
输出：种草图、标题、提示词、素材标签
```

知识库驱动 SOP 则可以使用：

```text
公众号 IP 内容 SOP
输入：IP 知识库文档、用户意图、平台、主题
步骤：Agent 读取知识库 -> 多轮调整 Prompt -> 生成大纲 / 正文 -> 发布检查 -> 人审 -> 导出
输出：文章、引用来源、Prompt、审核报告
```

### 5.4 文案生成

- 公众号长图文。
- 小红书笔记和标题。
- 抖音 / 视频号口播脚本。
- 知乎 / B 站深度稿。
- 详情页模块文案。
- 绿幕文案图内容。

### 5.5 图片生成

- 小红书种草图。
- 详情页图。
- 海报图。
- 封面图。
- 产品卖点图。
- 绿幕文案图。
- 图片生成必须记录提示词、产品图、参考图、模型和参数。

### 5.6 视频素材生产

v2 不把视频定义成“成片生成”，而是定义成“视频片段素材生产”：

- 15 秒图生视频素材。
- 氛围视频素材。
- 产品场景动效。
- 视频提示词。
- 可复制到第三方平台的视频 Prompt。
- 第三方生成后的成品视频可选导入。

视频生成路径：

| 模式 | 用途 | 状态 |
| --- | --- | --- |
| `internal-api` | 成本可接受时在软件内调用 Vidu / Runway / 其他 API。 | 后续增强，可保留抽象。 |
| `manual-external-prompt` | 软件生成视频 Prompt，用户手动复制到 RunningHub / 第三方平台。 | v2 优先。 |
| `manual-video-import` | 用户可选把第三方生成后的视频文件导入素材库，并关联原 Prompt。 | 可选能力，不跟踪外部任务。 |

边界：

- 第三方平台生成过程脱离软件，软件不维护外部任务状态。
- 软件不导出第三方平台任务文件，也不假设第三方平台支持回调。
- 第三方平台唯一回到软件的产物只能是用户手动导入的成品视频文件。

### 5.7 素材库

素材必须支持：

- 文件引用。
- 类型：文案、图片、视频、绿幕图、manifest、视频 Prompt 记录。
- 平台：公众号、小红书、抖音 / 视频号、B 站、知乎、电商详情页。
- 状态：草稿、待审、通过、驳回、已导出、已复制到外部。
- 来源：输入源、来源引用、Prompt Pack、运行追溯、模型参数。
- 标签：主题、产品、场景、人群、风格、用途。

### 5.8 导出

支持：

- Markdown 文案。
- 图片素材文件夹。
- 视频 Prompt 文本 / Markdown。
- 混剪素材包 manifest。

## 6. 非目标

- 不做完整混剪软件。
- 不做视频时间线、多轨剪辑、转场和成片渲染。
- 不做默认全自动发布。
- 不做 SaaS 形态、租户体系、服务端计费后台或云端团队空间。
- 不做多人权限和企业后台。
- 不做复杂云端素材库。
- 不做不可追溯的 AI 自动编造知识。
- 不强制把知识库先拆成数据库表。
- 不把 Agent 多轮读文档和调 Prompt 简化成一次性 RAG 摘要。
- 不要求所有内容任务都先绑定知识库。
- 不恢复 canvas 拖拽或 SOP 表单作为普通用户入口。
- 不做 RunningHub / 第三方视频平台任务包导出。
- 不跟踪第三方视频平台的任务状态。

## 7. 验收标准

- 至少能导入个人 IP 知识库和产品项目知识库两类 DOCX / Markdown 文档。
- Lime App Server Agent 能基于知识库文档和用户意图完成多轮 Prompt 草稿调整。
- 无知识库时，能基于参考图和产品资料反推 Prompt，并生成同风格图片。
- 参考视频能被拆解成脚本结构、镜头描述和视频片段任务草稿。
- 至少 3 条内容生产路径能进入同一套运行追溯口径。
- 内容制造批次 / 运行追溯可停在人工审核、待配置或待补资料状态。
- 素材库能展示每个产物的来源运行追溯、输入源、Prompt 版本和模型。
- 视频 Prompt 能复制到第三方平台；第三方成品视频可选导入并追溯原 Prompt。
- 内部视频 API 未配置时不能伪造成功。
- 混剪素材包导出后包含文件和 manifest。
- 普通用户不需要打开 canvas 或 SOP 表单即可完成素材生产、审核和交接。
- 高级用户查看复杂链路时，应读取内容制造批次和运行追溯，不写回旧 WorkflowDefinition。
