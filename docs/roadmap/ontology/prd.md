# 布谷AI内容工厂 Ontology PRD：内容生产知识地图

更新时间：2026-05-28  
状态：Draft

## 1. 背景

布谷AI内容工厂 v2 已经把“知识库 -> 场景库 -> 提示词组 -> 图片 / 视频 Prompt -> 素材库”跑成主链。但真实业务里，用户会不断提出更复杂的内容工程需求，例如：

- 帮我把产品卖点拆细。
- 帮我穷举所有人群、痛点、场景和内容角度。
- 帮我从评论里找真实痛点。
- 帮我判断哪些卖点有证据，哪些不能写。
- 帮我把同一套产品资料用于小红书、抖音、公众号、详情页和私域。

如果每次都把原始文档直接交给 LLM，模型会反复重命名、漏掉组合、混淆事实和推断，甚至编造没有证据的功效。Ontology 的目标是把这些“内容生产事实”和“关系”沉淀成可复用结构，让 LLM 在结构内生成，而不是自由发明。

这里的 Ontology 不是先做完整 OWL / RDF 平台，而是先做适合内容工厂的轻量知识地图：概念、关系、证据、约束、覆盖矩阵和审核状态。

进一步看，品牌舆论和获客不是静态内容流水线，而是动态的有机系统：热点、竞品动作、评论反馈、素材表现和平台规则会持续变化。Ontology 需要从“知识地图”升级为“操作地图”：每个运营、内容工程师和 Agent 都可以在权限边界内组合资源、触发动作、留下复盘，让内容生产从临时 prompt 变成可指挥、可复用、可学习的操作系统。

## 2. 产品定位

### 2.1 一句话定位

Ontology 是布谷AI内容工厂的内容生产知识地图和内容作战操作层，用来稳定拆解卖点、穷举场景、约束 Prompt、追溯证据、快速编组资源、记录行动结果，并沉淀可复用内容资产。

### 2.2 核心主张

1. Ontology 不是用户直接编辑的复杂图数据库。
2. Ontology 不是替代知识库、场景库或 Prompt 工作台，而是在它们之间建立稳定结构。
3. Ontology 不是一次性 LLM 输出；生产级构建必须拆步骤、可校验、可人审。
4. Ontology 运行时事实源优先是本地 JSON；RDF / OWL 只是后续互操作导出。
5. 所有用户可见内容主张必须可追溯来源；没有证据的主张只能标记为待验证，不能伪造成事实。
6. Ontology 对外发布必须对齐 Agent Knowledge v0.7.0 ontology-aware 知识包，保证知识库、Prompt 工作台和后续 Agent 客户端使用同一数据标准。
7. Operational Ontology 只把合法、真实、可审核的内容行动纳入系统，不做虚假舆论操控、自动刷量或绕过平台规则的动作。

## 3. 用户问题

| 用户问题 | 影响 |
| --- | --- |
| 卖点拆解每次生成口径不同。 | 同一产品在不同渠道表达不一致，审核成本高。 |
| 用户要求“穷举”，但 LLM 列表容易漏项。 | 场景、痛点、人群和内容角度覆盖不完整。 |
| 评论、客服问题和竞品内容里有大量真实语言。 | 不结构化就难以进入 Prompt 和 SOP。 |
| 内容主张缺少证据。 | 容易生成夸大、违法或无法审核的内容。 |
| 场景库、提示词组、素材库之间缺少统一关系。 | 成功素材无法反哺方法论和后续生产。 |
| 热点、评论和竞品动作变化很快。 | 运营无法快速把新信号转成目标、资源包、SOP 和复盘记录。 |
| 团队和 Agent 之间缺少统一指挥层。 | 每个人都在单点生成内容，资源不能迅速组合，经验也难以沉淀。 |
| 新行业类型数量未知。 | 预设枚举不够，完全自由生成又失控。 |
| Ontology 没有标准答案。 | 必须引入版本、审核、覆盖率和质量评分，而不是追求一次生成正确。 |

## 4. 产品目标

1. 支持从品牌 / 产品知识库、IP 知识库、产品 brief、SKU 表、用户评论、客服问答、竞品内容和成功素材中抽取候选概念。
2. 支持内容生产核心类型：产品、功能、属性、卖点、利益、痛点、人群、场景、证据、异议、禁用表达、渠道、内容角度和素材。
3. 支持关系建模：功能支撑卖点、卖点解决痛点、证据支持主张、场景适配人群、素材覆盖场景、Prompt 派生自概念组合。
4. 支持同义词归一、重复概念合并、概念粒度检查和孤立概念检查。
5. 支持卖点拆解矩阵：功能、属性、收益、痛点、证据、人群、场景、异议和表达角度。
6. 支持场景穷举矩阵：人群、痛点、触发时刻、空间、动作、情绪、渠道、素材类型。
7. 支持证据状态：已证实、弱证据、待验证、禁止使用。
8. 支持规则校验：无证据主张、敏感表达、重复概念、过粗 / 过细粒度、关系缺失、来源缺失。
9. 支持人工审核：通过、驳回、合并、拆分、改名、降级为待验证。
10. 支持把审核通过的结构输出到场景库、PromptDraft、PromptGroup、SOP 和审核台。
11. 支持成功素材回写 Ontology，标记哪些组合产生过高质量素材。
12. 支持将审核后的 Ontology 导出为 Agent Knowledge v0.7.0 ontology-aware 知识包，包含 `KNOWLEDGE.md`、`ontology/`、`metadata.primaryOntology` 和 provenance。
13. 支持 Operational Ontology 对象：`Signal`、`Objective`、`CampaignCell`、`ResourceBundle`、`ActionType`、`ActionLog`、`DecisionGate` 和 `FeedbackLoop`。
14. 支持把审核通过的资源组合快速触发标准动作，例如生成 Prompt、补证据、发起审核、启动 SOP 和回写覆盖矩阵。
15. 支持 v1 导出 JSON-LD / RDF / Turtle 之一，便于和外部知识图谱工具互操作。

## 5. 用户角色

| 角色 | 目标 | 典型动作 |
| --- | --- | --- |
| 品牌负责人 | 保证卖点、语气和合规边界稳定。 | 审核主张、证据、禁用表达和品牌用词。 |
| 新媒体运营 | 快速找到选题、场景和内容角度。 | 选择人群 / 痛点 / 平台，生成 Prompt 或脚本。 |
| 电商运营 | 把产品资料拆成详情页、主图和卖点图结构。 | 导入 SKU 和 brief，生成卖点矩阵。 |
| 短视频运营 | 穷举视频脚本角度和 15 秒素材场景。 | 选择场景组合，生成视频 Prompt。 |
| IP 主理人 | 保持人设、观点和语言长期一致。 | 审核 IP 观点、语言规则和场景延伸库。 |
| 审核人员 | 判断内容是否有证据、可发布、可复用。 | 查看来源、证据、风险和覆盖状态。 |
| 内容工程师 | 维护类型体系、抽取规则和校验规则。 | 配置 schema、规则、SOP 映射和导出。 |
| 增长负责人 | 围绕获客目标快速编组资源。 | 选择信号、目标、渠道、SOP 和资源包，复盘行动效果。 |
| Agent 操作者 | 在权限边界内调度 Agent 执行内容动作。 | 选择 ActionType，检查证据和审核状态，提交行动记录。 |

## 8. 端到端主路径

| 路径 | 主流程 | 完成定义 |
| --- | --- | --- |
| 产品卖点拆解 | 产品 brief / SKU -> 候选概念 -> 卖点矩阵 -> 证据校验 -> 人审 -> 场景库 / PromptDraft | 每条卖点可追溯事实和证据状态。 |
| 评论痛点穷举 | 评论 / 客服问题 -> 聚类痛点 -> 异议和原声 -> 人群 / 场景矩阵 -> 选题和脚本角度 | 每个痛点至少保留一条用户原声证据。 |
| 品牌场景生产 | 品牌 / 产品知识库 -> Ontology -> 覆盖矩阵 -> 10 组 UGC 图片 / 视频 Prompt | Prompt 只使用审核通过或明确标记的事实。 |
| IP 一致性生产 | IP 知识库 -> IP 概念关系 -> 平台场景 -> 文案 / 口播 / 私域 Prompt | 所有内容引用同一 IP 版本和语言规则。 |
| 素材库反哺 | 审核通过素材 -> 关联组合 -> 标记高表现原因 -> 更新覆盖矩阵 | 后续生成可优先使用已验证组合。 |
| 动态获客作战 | Signal -> Objective -> CampaignCell -> ResourceBundle -> ActionType -> ActionLog -> FeedbackLoop | 每次行动可追溯目标、资源、权限、证据、产物和复盘结果。 |

## 9. 功能范围

### 9.1 MVP 范围

- 轻量 Ontology 工作区。
- 核心类型和关系 schema。
- 从文本输入源抽取候选概念。
- 卖点拆解矩阵。
- 评论痛点聚类。
- 场景覆盖矩阵。
- 证据和约束校验。
- 人工审核。
- 输出 SceneCard / PromptDraft。
- 本地 JSON 事实源和运行记录。
- 最小 ActionLog：记录从 ready coverage row 到 PromptDraft / WorkflowRun 的行动链路。

### 9.2 v1 范围

- IP Ontology。
- 成功素材回写。
- Prompt 工作台按相关子图注入上下文。
- 审核台展示 Ontology 风险和覆盖。
- SOP 可按 Ontology 组合批量运行。
- Agent Knowledge v0.7.0 ontology-aware 知识包导出。
- Signal、Objective、CampaignCell、ResourceBundle、ActionType 和 DecisionGate。
- 标准动作执行前校验权限、证据、审核状态和渠道风险。
- JSON-LD / RDF / Turtle 导出之一。

### 9.3 远景范围

- 行业模板库。
- 品牌专属 Ontology 版本演进。
- 跨项目复用的概念映射。
- Ontology diff、merge 和迁移。
- 多 CampaignCell 协同、行动复盘看板和资源调度推荐。
- 与外部知识图谱、搜索、SPARQL 或企业数据系统互操作。

## 10. 非目标

- 不在 MVP 做完整 OWL 编辑器。
- 不在 MVP 引入云端图数据库。
- 不把 Ontology 变成普通用户必须手工编辑的大表。
- 不允许无证据主张直接进入可发布内容。
- 不用一次性端到端 prompt 替代分步构建和审核。
- 不做自动发布。
- 不做多人权限和 SaaS 协作后台。
- 不把 RDF / OWL 作为运行时强依赖。
- 不把 `ontology/` 当作 Skill、workflow、prompt 指令或脚本目录。
- 不做虚假舆论操控、自动刷量、伪造互动或绕过平台审核。

## 11. 验收标准

1. 能导入产品 brief / SKU / 评论文本并生成 Ontology draft。
2. 能输出卖点矩阵，且每个卖点有证据状态。
3. 能输出场景覆盖矩阵，并区分已覆盖、缺证据、缺素材和待审核。
4. 能识别无证据主张、重复概念、孤立概念和敏感表达。
5. 能人工审核概念和关系，并阻止未审核 / 禁止项进入 Prompt。
6. 能从审核通过的组合生成 SceneCard 或 PromptDraft。
7. 能保存构建运行记录，记录输入源、模型、提示词版本、校验问题和人工审核结果。
8. 能保存最小 ActionLog，记录从覆盖矩阵组合到 PromptDraft / WorkflowRun 的行动链路。
9. 能导出符合 Agent Knowledge v0.7.0 的 ontology-aware 知识包，并通过包结构校验。
10. 未配置模型时显示 blocked，不伪造 Ontology。

## 12. 风险与待确认

1. 类型体系不能过早追求“大而全”，否则会拖慢 MVP；先覆盖内容生产高频对象。
2. 覆盖矩阵可能组合爆炸，需要按目标渠道、人群优先级和证据强度排序。
3. LLM 抽取质量依赖输入源质量；必须保留人工审核和待补字段。
4. IP Ontology 容易和品牌 / 产品 Ontology 混用，v1 需要明确隔离。
5. 行业合规规则可能需要独立规则包，不应硬编码在通用 schema 里。
6. 动态作战层容易过度膨胀为项目管理系统；v1 只做围绕内容行动的信号、资源包、动作和日志。
7. 舆论和获客场景有滥用风险；必须把证据、平台规则、品牌审核和不可执行动作写进 DecisionGate。
