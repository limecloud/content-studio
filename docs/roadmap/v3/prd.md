# 布谷 AI v3 PRD：支持 OEM 的品牌前台与素材中台

更新时间：2026-05-23  
状态：Draft

## 1. 背景

`content-studio` 已经承担了内容生产端的工作台职责，但它不适合继续承载品牌官网、案例展示、素材分发和 OEM 前台。这一层应该落到 `bugu`：对外承接品牌形象，对内承接租户配置、素材资产和账号 / 控制台体验。

`limecore` 未来会部署到 Railway，继续作为通用中台，提供登录、应用、OAuth、权益和租户抽象；它不应该背负 Bugu 的案例内容、素材内容或站点页面逻辑。

v3 的目标是把 Bugu 做成一个**配置驱动的 OEM 品牌站点系统**，而不是一个重型 SaaS 后台，也不是一个内容生产引擎。

## 2. 产品定位

### 2.1 一句话定位

Bugu v3 是支持 OEM 的品牌前台和素材中台，用于承接品牌官网、案例库、素材库、下载中心、自有登录 / 控制台，以及多租户站点配置。

### 2.2 核心主张

1. Bugu 不是业务数据库中台。
2. Bugu 不是内容生成引擎。
3. Bugu 不是 Railway 上的重型 OEM 后端。
4. Bugu 是可移植部署的品牌前台 + BFF + 轻量内容管理层，Cloudflare 只是参考部署。
5. Bugu 通过配置渲染站点；每个 OEM 可以有独立主域名和独立前台部署参数，而不是共享 `bugu.run` 下的业务路径。

## 3. 目标用户

| 角色 | 目标 | 典型动作 |
| --- | --- | --- |
| 品牌方 / OEM 客户 | 拥有自己的品牌页面、案例页和下载页。 | 选择主题、发布内容、替换案例和 CTA。 |
| 布谷运营人员 | 维护品牌内容和站点配置。 | 上架案例、更新素材、发布下载版本。 |
| 租户管理员 | 管理登录、控制台和品牌前台配置。 | 登录、查看权限、管理站点块。 |
| 访问者 | 快速理解产品价值并完成下载或登录。 | 浏览首页、案例、素材、下载。 |

## 4. 用户问题

| 当前问题 | 影响 |
| --- | --- |
| OEM 品牌页面和内容资产不独立。 | 站点会混用不同品牌语义，难以维护。 |
| 案例 / 素材散落在不同仓库或手工页面。 | 更新成本高，无法按租户复用。 |
| 账号前端、控制台和官网语义不一致。 | 用户会跳出品牌壳，体验割裂。 |
| 如果把内容资产放进 Railway 中台。 | 中台会被业务内容拖重，失去抽象能力。 |

## 5. 产品目标

1. 支持 `bugu.run` 作为默认品牌站。
2. 支持租户级 OEM 站点，通过 `primaryDomain` 渲染不同品牌壳，例如 `seenx.run`；`{tenant}.bugu.run` 和 `/o/{tenant}` 只作为别名 / 预览入口。
3. 支持首页、案例页、素材页、下载页、登录页和控制台页。
4. 支持租户级站点配置、主题变量和导航配置。
5. 支持案例、素材和下载清单的独立管理与发布。
6. 支持账号前端与控制台继续调用 LimeCore public API。
7. 支持按租户隔离内容资产，不串数据。

## 6. 范围与非目标

### 6.1 范围

- 品牌站首页、案例、素材、下载、登录、控制台。
- OEM 站点配置、主题、页面区块和资源资产。
- 站点内容的读取、发布和预览。
- 账号 / 控制台对接 LimeCore public API。
- 云端静态资产与轻量元数据管理。

### 6.2 非目标

- 不做 Railway 上的业务型内容数据库。
- 不让前台直连 MySQL / Postgres；阿里云 / 私有化可以通过 Bugu store 适配器接 RDS、PolarDB、MySQL 或 Postgres。
- 不做重型 CMS、任务流、CRM 或多租户计费后台。
- 不做内容生成引擎。
- 不把 `content-studio` 客户端打包进 Bugu 站点。

## 7. 信息架构

### 7.1 公共站点

```text
bugu.run
├── 首页
├── 案例
├── 素材
├── 下载
├── 课程 / 服务
├── 登录
└── 控制台
```

### 7.2 OEM 站点

```text
seenx.run
├── 品牌首页
├── 品牌案例
├── 品牌素材
├── 品牌下载
├── 品牌登录
└── 品牌控制台
```

OEM 正式入口优先使用客户自己的主域名，例如 `seenx.run`。`seenx.bugu.run` 或 `bugu.run/o/{tenant}` 只用于预览、兼容或绑定前过渡，不是正式业务路径。

## 8. 用户故事

| ID | 角色 | 用户故事 | 验收条件 |
| --- | --- | --- | --- |
| US-01 | 品牌方 | 我想创建一个 OEM 站点并套用品牌主题，这样可以快速上线自己的品牌页。 | 站点主题、导航和首页区块可配置。 |
| US-02 | 运营人员 | 我想更新案例和素材卡片，不改代码就能发布。 | 新内容进入 D1 / R2 后，前台可见。 |
| US-03 | 访问者 | 我想直接看到案例、素材和下载入口。 | 首页首屏和导航能快速导向对应页面。 |
| US-04 | 用户 | 我想登录后进入同品牌控制台。 | 登录页与控制台保持品牌一致，不跳出站点。 |
| US-05 | 租户管理员 | 我想按租户隔离站点内容。 | 不同租户的主题、案例和下载互不串数据。 |
| US-06 | 平台运营 | 我想统一维护 API 代理和站点配置。 | 只通过 `api.bugu.run` 暴露 public client 能力和 OEM 管理接口。 |

## 9. 技术与部署边界

- 前台可部署到 Cloudflare Pages、阿里云 OSS 静态站点 + CDN，或自托管 Next.js。
- API 可由 Cloudflare Worker、阿里云函数计算 / SAE / ECS，或私有化 Node 服务承担。
- 站点元数据通过 Bugu store 契约读写；Cloudflare 参考部署用 D1，阿里云 / 私有化可用 RDS、PolarDB、MySQL 或 Postgres。
- 图片、封面、下载包和预览资源通过对象存储适配器读写；Cloudflare 参考部署用 R2，阿里云可用 OSS，私有化可用 S3 / MinIO。
- 高频配置和租户映射可用 KV、Redis、Tair 或配置中心缓存。
- LimeCore 只提供公共 client API 和通用 OEM 抽象，不直接承载 Bugu 内容。

## 10. 验收标准

1. `bugu.run` 首页可正常访问，且具备明确的案例、素材和下载入口。
2. 至少一个 OEM 租户站点可以按配置渲染。
3. 登录和控制台保持当前 OEM 品牌，不跳转其他品牌后台。
4. 案例、素材、下载三类内容都能独立管理并发布。
5. `api.bugu.run` 只代理允许的 public client 能力和 Bugu 管理接口。
6. Bugu 不依赖 Railway 的 MySQL / Postgres 来承载站点内容事实源；跨云 / 私有化只能通过 Bugu 适配器替换运行时。

## 11. 风险与待确认

1. wildcard 子域名只作为别名和预览入口，正式 OEM 入口优先按客户独立主域名规划。
2. 案例和素材是否需要分租户审核流，需要在实现阶段确认权限粒度。
3. 登录态是继续沿用当前 token 模式，还是迁移为更强的 cookie 会话，需要在实现前定版。
