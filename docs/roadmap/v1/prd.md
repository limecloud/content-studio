# 布谷AI内容工厂 v1 PRD：AI 电商内容生产工作台

更新时间：2026-05-19
状态：Archived historical source

> 归档说明：本 PRD 保留 v1 阶段的产品范围记录。文中关于旧本地 SDK runtime 的表述均为历史背景；当前 Agent runtime 与打包架构以 v2 路线和 `docs/roadmap/limeagent/` 为准。

## 1. 背景

用户给出的 5 张截图展示了一个成熟的「AI 电商图片工作台」形态：左侧按图片 / 视频划分能力，中间是上传、提示词、模板和结果预览，右侧统一管理模型、比例、分辨率和质量。2026-05-19 对上一代 Web 产品完成 Playwright 调研后确认：上一代最成熟的是图片模板参数化、统一模型配置、批量模式壳和 内容助手入口；视频页仍是开发中占位。布谷AI内容工厂 v1 在此基础上补齐文章生成、已成型知识库接入、素材库和生成历史，目标是在 Electron + 协议化生成服务路由的新项目中形成面向电商内容生产的第一条主链。

调研事实源：`docs/roadmap/v1/yanshi-legacy-research.md`。

## 2. 用户问题

| 用户问题 | 影响 |
| --- | --- |
| 运营有产品图和参考图，但不知道如何写稳定提示词。 | 生成结果不稳定，需要反复试错。 |
| 图片和视频工具分散，参数和模型配置不统一。 | 每次切换场景都要重新理解工具。 |
| 爆款视频可以参考，但拆解、复刻脚本和分镜生成没有闭环。 | 视频复刻停留在人工分析和手工改稿。 |
| 生成结果缺少历史、预览和导出。 | 无法沉淀为可复用资产。 |
| 合规、精修和 内容助手分散。 | 生产前后检查成本高。 |
| 能力 没有可视化管理。 | 无法确认哪些提示词能力已安装、可用、失效或参与当前生成。 |
| 已经整理好的产品知识库和个人 IP 知识库没有工作台承载。 | 文章、提示词和脚本无法稳定引用统一事实源。 |
| 文章生产与图片 / 视频生产割裂。 | 同一产品要重复整理卖点、口吻和素材，效率低。 |

## 3. 目标

1. 支持图片生成：产品图 / 参考图上传、预设模式、提示词输入、生成预览和导出。
2. 支持全局参数：文字、图片、视频模型，生成数量，图片比例，分辨率，质量。
3. 支持模型配置弹窗：统一 API 端点、API Key 和三类模型配置。
4. 支持视频复刻三步流：视频拆解、脚本生成、视频生成。
5. 支持 skills 驱动的提示词与拆解逻辑，但用户界面以「预设提示词」「生成模式」「拆解维度」表达。
6. 支持 skills 管理：扫描内置 / 工作区 skills，安装内置 skills 到工作区，启用 / 停用生成链路使用的 skills，并展示校验错误。
7. 支持文章生成：基于知识库和产品素材生成大纲、正文、标题、摘要、发布检查和 Markdown 导出。
8. 支持知识库：选择内置产品型 / 个人 IP 型知识库，导入已成型知识库文件，关键词检索，选择引用并注入文章、提示词和脚本生成。
9. 支持品牌提示词包和产品场景库：从已成型知识库派生品牌口吻、视觉风格、合规边界、平台约束和场景卡。
10. 支持素材库和生成历史：本地记录文章、图片、脚本、视频队列和关键参数。
11. 首轮交付必须有明确空态、加载态、错误态和成功态。

## 3.1 上一代产品继承策略

上一代产品不是完整内容工厂，但有几块已经被实战验证，v1 必须吸收：

| 上一代能力 | 继承方式 | v1 边界 |
| --- | --- | --- |
| 图片模板参数化 | 9 个模板都展示各自参数表单，参数进入图片生成服务 prompt。 | 只做图片模板，不扩展成在线模板市场。 |
| 模型配置 | 统一端点、Key、文字 / 图片 / 视频模型配置。 | 不按模型名前缀自动猜协议，改用显式 生成服务路由。 |
| 批量模式 | 展示任务统计、多线程和文件夹入口。 | v1 只做受控 Shell，不伪造批量执行成功。 |
| 内容助手 | 保留 助手 对话入口、快捷指令概念。 | v1 不把通用对话作为主链，等本地 内容助手服务接入后再启用。 |
| 合规检测 / 图片精修 | 保留入口和业务说明。 | v1 不做假按钮，未接入前明确后续接入。 |

## 4. 用户角色

| 角色 | 目标 | 典型动作 |
| --- | --- | --- |
| 电商运营 | 快速做商品主图、海报和详情页配图。 | 上传产品图，选模板，改提示词，导出。 |
| 内容策划 | 把爆款视频拆成可复用脚本。 | 导入视频，选择拆解维度，生成复刻脚本。 |
| 设计助理 | 基于参考图做风格迁移和精修。 | 上传参考图，选择画面比例和质量。 |
| 短视频剪辑 | 根据新产品信息生成分镜和视频队列。 | 填产品信息，生成脚本，再生成分镜。 |
| 新媒体运营 | 基于商品资料和品牌口吻写文章。 | 选择知识库引用，生成大纲，改正文，导出 Markdown。 |
| 品牌 / 商品负责人 | 使用已成型知识库统一事实和禁用表达。 | 选择产品知识库或个人 IP 知识库，检查引用和合规边界。 |

  - 发布检查：v1 inside article flow

### 5.3 右侧全局参数

右侧全局参数必须在图片和视频页保持同一位置和视觉层级：

- 图片模型：默认示例 `gpt-image-2`
- 文字模型：默认示例 `gemini-3.1-pro-preview`
- 视频模型：默认示例 `gemini-3.1-flash-image-preview`
- 生成数量：单次 / 并发 / 内联，v1 只启用单次
- 图片比例：1:1、4:5、5:4、3:4、4:3、2:3、3:2、9:16、16:9、21:9、9:21、1:8
- 分辨率：1K / 2K / 4K，v1 默认 2K
- 图片质量：低 / 中 / 高，v1 默认中

### 5.4 skills 管理

skills 管理是面向高级用户和内容团队的 skills 面板，用来解释「当前工作台为什么会这样写提示词 / 拆解视频」。

- 来源：内置 skills、工作区 `.claude/skills`、工作区 `.claude/skills`，兼容读取 `.agents/skills`。
- 状态：有效、无效、已安装到当前工作区、当前生成启用。
- 操作：扫描刷新、查看详情、安装内置 skills、启用 / 停用、复制路径。
- 详情：名称、描述、来源、适用场景、`globs`、`alwaysAllow`、`requiredSources`、校验错误。
- 约束：v1 不做在线市场、不做远程安装、不做用户编辑器；编辑仍交给文件系统和外部编辑器。

### 5.5 知识库与资产

知识库只做本地事实源，不做复杂在线协作，也不做 AI 自动搭建知识库。

- v1 知识库来源：内置产品型知识库、内置个人 IP 型知识库、用户导入的已成型知识库文件。
- 产品型知识库结构：科学 / 行业基础、品牌定位、产品矩阵、卖点体系、场景话术、异议处理、合规红线、Q&A、规格和参考资料。
- 个人 IP 型知识库结构：人物档案、定位、时间线、故事素材、方法论、价值观、金句库、写作风格、多场景介绍、禁忌边界。
- v1 输入：DOCX、Markdown、纯文本、JSON；PDF / 网页抓取 / 差评抓取 / 调研报告自动生成进入后续版本。
- 检索方式：关键词、标签、知识库类型、章节类型；向量检索先不作为 v1 必须项。
- 引用方式：用户手动勾选引用片段，生成请求带 `sourceId`、`sectionType` 和 `excerpt`。
- 资产记录：文章草稿、图片结果、脚本结果、视频队列、使用的知识引用和模型参数。

### 5.6 内容工程主链

案例文档中的顺序更接近「知识库 -> 场景 / 提示词 -> 文案 / 脚本 / 素材 -> 视频」，而不是直接「知识库 -> 图片 -> 视频」。

v1 采用以下主链：

```text
已成型知识库
-> 品牌 / 产品提示词包
-> 产品场景库
-> 文案 / 脚本 / 图片提示词
-> 图片素材
-> 视频提示词 / 图片转视频素材
-> 视频生成队列
```

关键约束：

- 品牌 / 产品提示词包包含品牌口吻、视觉风格、卖点表达、禁用表达、平台限制和模型提示词片段。
- 产品场景库包含目标人群、痛点、使用场景、画面设定、核心卖点、口播方向和素材建议。
- 图片素材优先由产品场景库和图片提示词生成。
- 视频素材可以使用图片素材做图生视频，也可以使用脚本、参考视频拆解和外部素材；不强制所有视频都必须由图片生成。

## 6. 功能需求

### FR-01 模型配置

用户可以打开设置弹窗并配置：

- API 端点（统一）
- API Key（统一）
- 文字模型
- 图片模型，可填多个候选
- 视频模型
- 每组模型支持「获取模型」按钮，但 v1 可以先返回配置端点可用模型或 mock 列表

验收：保存后右侧全局参数读取配置值；API Key 不暴露给 Renderer 日志。

### FR-02 图片生成输入

用户可以：

- 上传 0-10 张产品图
- 上传 0-6 张参考图
- 输入详细提示词；输入框初始保持为空，不把系统兜底提示词预填到界面
- 上传图片后可在提示词中输入 `@` 点名某张产品图或参考图，生成请求需把被点名图片标记为重点参考
- 选择自由模式或预设提示词
- 选择智能生成或固定生成
- 选择图片生成模板
- 为 9 个模板填写参数化表单：产品名称、场景、版式、分区、拍摄者、3D 类型、拆解策略、电影风格或美食品类

验收：未上传产品图时可以生成纯提示词图；上传后生成请求包含素材引用、模式、模板和 `templateInputs`；`@图片` 引用会进入图片引用清单并在对应协议 payload 中增加重点参考说明；模板参数以中文字段写入 生成服务 prompt 和生成日志。

### FR-03 图片生成与预览

用户点击「启动渲染引擎」后：

- 按当前全局参数生成
- 把知识引用、场景卡、模板、模板参数、素材引用和模型协议打成统一 payload
- 主区展示生成中状态
- 成功后生成预览图网格
- 支持导出图片
- 支持生成日志查看参数、时间、错误

验收：至少支持单次生成 1 张；失败时展示可重试错误态；生成服务 缺失时返回 `blocked` 并记录原因，不产生占位图。

### FR-04 视频拆解

用户可以导入本地视频或粘贴视频链接，并选择拆解维度：

- 开头钩子
- 钩子评分
- 语气风格
- 卖点逻辑
- 镜头运镜
- 画面构图
- 关键词视觉元素
- 字幕口播
- 情绪曲线
- 节奏密度
- 视觉风格
- 转化设计
- 爆点因素
- 内容公式
- 转场方式
- 用户停留点

验收：生成结构化拆解结果，并可用于下一步脚本生成。

### FR-05 视频脚本生成

用户根据拆解结果填写新产品信息：

- 产品名称
- 场景背景
- 字幕选择
- 视频语音
- 自定义需求
- 产品图 / 背景参考
- 新视频比例、镜头和时长

验收：生成新视频脚本内容，脚本包含镜头、口播、画面、字幕和节奏说明。

### FR-06 视频生成队列

用户在脚本生成后可以进入视频生成：

- 使用分镜图 / 上传图片 / 上传视频作为素材
- 输入视频提示词
- 按视频模型、比例、时长生成
- 展示生成历史

验收：v1 可以先实现分镜图和视频生成占位队列；真实视频模型可接入后替换。

### FR-07 skills 管理

用户可以打开 skills 管理页并完成：

- 查看内置、工作区 skills 列表。
- 区分有效 / 无效 skills，并看到 `SKILL.md` 缺失或 frontmatter 错误。
- 将内置 skills 安装到当前工作区。
- 为当前生成链路启用 / 停用 skills。
- 在生成请求中带上已启用的 `selectedSkillSlugs`。

验收：至少 4 个内置内容 skills 可见；没有工作区 时安装按钮禁用并说明原因；无效 skills 不可启用；用户能明确看到当前生成会使用哪些 skills。

### FR-08 文章生成

用户可以基于知识库资料生成文章：

- 选择文章类型：公众号长文、小红书笔记、商品种草文、详情页文案、短视频口播稿。
- 填写主题、目标读者、平台、语气、字数范围和自定义要求。
- 选择知识库引用、产品素材和启用的文章类 能力。
- 生成标题候选、大纲、正文和摘要。
- 运行发布检查，输出问题、修改建议和风险等级。
- 导出 Markdown，并写入生成历史。

验收：正文必须可追溯到本次引用的知识条目；没有引用时也能生成，但 UI 明确提示「未使用知识库」；导出文件名不硬编码平台路径。

### FR-09 知识库

用户可以使用已成型知识库：

- 选择内置产品型知识库或个人 IP 型知识库。
- 导入 DOCX、Markdown、纯文本、JSON 等已成型知识库文件。
- 查看章节结构、知识库类型、标签、摘要和原文。
- 通过关键词、标签和章节类型检索知识库。
- 选择引用片段并发送到文章、图片提示词或视频脚本生成。

验收：知识库数据保存在当前工作区；v1 不提供从零搭建知识库、AI 自动整理调研资料、竞品抓取或差评采集；引用片段会写入生成日志。

### FR-10 品牌提示词包与产品场景库

用户可以从已成型知识库派生生成资产：

- 生成品牌 / 产品提示词包：品牌口吻、视觉风格、合规边界、平台约束、图片提示词片段、视频提示词片段。
- 生成产品场景库：人群、痛点、使用场景、画面、卖点、口播方向、素材建议。
- 从场景卡生成文章大纲、短视频脚本、图片提示词或视频提示词。
- 将提示词包和场景卡写入素材库，供图片生成和视频生成复用。

验收：图片和视频生成请求能追溯到使用的知识引用、提示词包和场景卡；用户可以手动编辑派生结果后再生成。

### FR-11 素材库与生成历史

用户可以查看本地生成资产：

- 按类型过滤：文章、图片、视频脚本、视频队列。
- 查看输入、模型、参数、知识引用、能力 和输出摘要。
- 从历史记录复制提示词、导出 Markdown 或打开本地结果。

验收：所有生成主链都至少写入一条结构化历史；失败任务也记录错误摘要，避免静默丢失。

### FR-12 入口占位

以下能力 v1 只做入口和说明，不做完整实现：

- 合规检测
- 内容助手：继承上一代 `/skill`、`/model`、`/help` 的产品概念，但等待本地 内容助手服务接入
- 图片精修
- 批量处理：可展示任务统计、多线程选择和文件夹入口，但不启动真实并发队列
- 定时任务：只在批量模式里展示后续接入说明
- 创意视频
- 自定义视频

验收：入口清晰显示「后续接入」或禁用态，不产生假可用按钮；批量 / 定时不得写入成功日志。

## 7. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 安全 | API Key 只在 Electron main process 持有，Renderer 不可读取。 |
| 可追溯 | 每次生成记录输入、模型、参数、模式、耗时和错误。 |
| 可引用 | 文章、提示词和脚本生成需要记录知识来源和引用片段。 |
| 稳定性 | 生成任务支持取消和错误重试。 |
| 跨平台 | macOS / Windows 路径使用 Electron API，不硬编码用户目录。 |
| 可扩展 | 图片 / 视频模型 生成服务 通过 adapter 接入，不写死单一模型。 |
| 可用性 | 主要按钮有明确 loading / disabled / success / failed 状态。 |
