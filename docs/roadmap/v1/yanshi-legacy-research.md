## 3. 图片页可继承能力

图片页结构已经验证为「左侧能力 / 中间生成 / 右侧参数」：

- 图片能力入口：图片生成、合规检测、图片精修。
- 处理模式：单次处理、批量处理、定时任务。
- 上传区：产品图 `0/10`，参考图 `0/6`。
- 提示词区：自由输入 + 预设提示词管理。
- 生成模式：AI 创建、导入、导出、自由模式、选择预设提示词。
- 预览区：图片预览大盘区和生成日志承载。
- 参数区：图片模型、文字模型、生成数量、比例、分辨率。

v1 继承边界：

- 单次图片生成必须真实可用。
- 批量处理先做 Shell、统计和状态，不伪造批量执行成功。
- 定时任务保持禁用或说明，只在批量能力稳定后接入。
- 合规检测、图片精修、内容助手先保留入口和后续接入说明。

## 4. 批量模式

批量模式点击后出现：

- 任务统计：任务总数、已完成、未完成、等待区、失败数量。
- 多线程：1-7 线程和智能模式。
- 上传区文案改为「点击选择文件夹」。
- 定时任务入口文案变为「设置定时批量执行」。

布谷AI内容工厂 v1 不直接实现并发任务调度；先把批量模式作为可见但受控的任务壳，等图片单次、日志和素材库稳定后再接任务队列。

## 5. 模型配置

上一代模型配置弹窗包含：

- 标题：模型配置。
- 预设说明：`WEB 演示预设`。
- API 连接：统一 API Key。
- 自动识别规则：模型名以 `gemini` 开头走 Gemini 原生模式，其他模型走 OpenAI 兼容模式。
- 模型字段：文字模型、图片模型、视频模型、内容助手模型。
- 浏览器本地持久化 key：`legacy_api_config`、`legacy_selected_models`、`legacy_save_path`、`legacy_skills_dir`。

布谷AI内容工厂 v1 已采用更稳的显式协议生成服务路由：

- Claude / Anthropic 官方链路：`claude-sdk`。
- Anthropic Messages 兼容网关：`anthropic-messages`。
- OpenAI Chat 兼容网关：`openai-chat` / `openai-chat-data-uri`。
- Gemini 原生：`gemini-generate-content`。

这比按模型名前缀自动猜协议更可控，适合桌面产品和真实用户配置。

## 7. 对布谷AI内容工厂 v1 的实现要求

1. 模板配置要成为共享事实源，Renderer 用来渲染表单，Main 生成服务 用来把参数转换为中文模型提示词。
2. 图片生成请求必须携带 `templateInputs`，并写入日志，方便历史复用。
3. 图片生成服务 prompt 必须包含「模板参数」，不能只把用户输入留在前端。
4. 真实生成服务 未配置时返回 `blocked`，不能用占位图伪装成功。
5. 内容助手、批量、定时、合规、精修只做清晰入口和接入说明，直到有真实业务链路。

## 8. 二次深度调研补充

2026-05-19 用户补充截图后，再次用本地 Playwright 覆盖 26 个交互步骤，调研产物临时保存在 `/tmp/yanshi-deep-research-20260519`。新增确认：

- 顶部技能操作包含 `AI创建`、`导入`、`导出`。
- `AI创建` 打开弹窗，用户用自然语言描述新技能，再由 AI 生成技能。
- 每个内置图片模板都有 `编辑` 按钮。
- 编辑弹窗包含 `直接编辑` 和 `AI 辅助修改` 两个 Tab。
- 直接编辑内容是完整 JSON 技能配置，包含 `id`、`name`、`version`、`author`、`icon`、`category`、`description`、`config`、`prompts`、`variables`。
- `详情页分区图` 的 JSON 里包含强约束 prompt、分区类型多选、默认比例和默认数量。
- 内容助手页左侧展示 `助手 已连接` 概念、快捷指令 `/skill` `/model` `/help`，主区在后端不可用时显示 `内容助手未启动`、`Failed to fetch`、端口 `19997`、`重试连接` 和 `独立窗口打开`。

布谷AI内容工厂 v1 对应实现策略：

1. 图片页必须补齐 `AI 创建`、`导入`、`导出 / 编辑` 操作条。
2. 模板编辑至少支持本次会话内的 JSON 直接编辑，并真实影响表单字段和生成 payload。
3. AI 辅助改技能和 AI 创建技能必须展示受控入口，但在本地 内容助手服务和技能写入权限接入前禁用执行按钮。
4. 内容助手入口从 disabled 改为可进入 Shell，展示快捷指令和端口边界，不伪造聊天成功。
